日期：2026-11-23 ｜ 口径：**只收有官方 API 说明文档页的接口**（`runninghub.ai/runninghub-api-doc-en/` 下可查），社区 AI 应用若无独立文档一律不列为正式接口

## 一、结论摘要

1. RunningHub 图生图有**三种调用形态**，文档完备度差异极大：
   - **标准模型 API**（`/openapi/v2/*`）：**43 条**图生图端点，每一条都有独立文档页（参数、枚举、示例齐全）——文档最全，但**本账号 apiType=NORMAL，全部 1014 调不动**（Circle24 实测）；
   - **Workflow API**（`/task/openapi/create`）：有文档（api-425761092/093），**NORMAL 账号实测可调**，跑的是自建 ComfyUI 工作流——模型能力由工作流内节点决定，是**当前唯一"有文档且可用"的图生图通道**；
   - **AI App API**（`/task/openapi/ai-app/run`）：只有平台通用文档，参数结构靠应用详情页（nodeInfoList 样例），Flux3图像编辑属此类——**不算"有接口文档"的通道**。
2. 若账号升级解除 1014，一线候选直接可用：**seedream-v5-pro / v5.5**（10 张参考图 + 像素级局部重绘 + 2K）、**nano-banana-pro**（10 图 + 4K + 10 档比例）、**FLUX.2 系**（与 Flux3 同门，32B 编辑模型）。
3. 我们上一轮实验的两个失败点恰好有文档承诺的对口解药：身份不保 → `imageUrls` 多参考图（≤10 张）；漂移失控 → "pixel-level local redraw"（seedream 系文档原文）。

## 四、参数速查（4 篇文档实抓核对）

| 接口 | 请求端点 | 关键参数（文档原文核对） |
| --- | --- | --- |
| seedream-v5-pro | `POST /openapi/v2/seedream-v5-pro/image-to-image` | prompt 必填 5–5000；**imageUrls ≤10**（PNG/JPEG）；resolution `1k/2k`（优先于宽高）；width/height 240–8192；outputFormat `jpeg/png`；结果查询 `/openapi/v2/query` |
| nano-banana-pro | `POST /openapi/v2/nano-banana-pro/edit-official-stable` | **imageUrls ≤10**；prompt 1–20000；resolution `1k/2k/4k`；aspectRatio 10 档（`1:1`…`21:9`） |
| f-2-dev/edit | `POST /openapi/v2/f-2-dev/edit` | 字段为**节点式**：`20##image` 单图必填、`17##text`、`46##select` 比例 9 档（含 Auto match）、`51##file_type`（PNG/JPEG/WEBP）、自定义宽高 256–1536 |
| qwen-image-3.0-pro | `POST /openapi/v2/qwen-image-3.0-pro/image-edit` | 1–3 张参考图 + 文本指令 |

> 观察：`f-2-dev/edit` 的 `节点ID##字段名` 参数暴露了标准模型 API 的本质——它也是平台预置的 ComfyUI 工作流，只是被文档化成了"模型端点"。多参考图能力在各端点间并不统一（数组 vs 单图节点）。

## 五、Workflow API：当前唯一"有文档且可用"的图生图通道

- 文档：`api-425761092`（create）/ `api-425761093`（status），端点 `POST /task/openapi/create`
- 契约：`apiKey` + `workflowId` + 可选 `nodeInfoList`（`nodeId`/`fieldName`/`fieldValue`）；可直塞整图 `workflow` JSON；`instanceType` = default 24G / plus 48G / ultra 84G；`webhookUrl` 回调
- 实测（Circle21）：NORMAL 账号可调；公开示例工作流 `1904136902449209346` 跑通；`getJsonApiFormat` 可读回公开工作流 JSON；**API 不能创建工作流**——须先在网页工作台搭一次，之后全自动
- 图生图用法：在工作台/市场找含图生图节点的工流（如 Seedream / FLUX.2 / Qwen Edit 节点）→ 上传图与 prompt 用 `nodeInfoList` 替换 → 固定变量实验照旧
- 可抄的现成素材（官方推荐位）：`FLUX3.0Klein文生图单双多图编辑全套工作流`、`MiniMax×Flux3 多图参考智能编辑 · 6步极速版`

## 七、下一步建议

1. **先定账号问题**：1014 是账号级别卡死，标准模型 API 文档再全也用不上；升级成本需你确认
2. **不升级的可行路线**：Workflow API + 工作台搭一个 Seedream 或 FLUX.2 图生图工作流 → 用同一套固定变量方法复测"身份保持/局部重绘"
3. **若升级**：优先 seedream-v5-pro 小矩阵（多图身份锁定 + 局部重绘两档），它同时命中我们上一轮两个失败点
4. 本报告不含社区 AI 应用的参数文档（无独立文档），Flux3图像编辑的实测结论见 `实验报告单.md`
