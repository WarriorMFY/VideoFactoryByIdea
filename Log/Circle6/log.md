## 0 · 规格（本轮自定，跑前先写死）

### 0.1 场景卡定位

沿用「一卡一绑」——一张场景卡绑定一张动作卡，只做定制强化，不为通用场景库。

职责边界：

| 项 | 内容 |
| --- | --- |
| 管 | 场地类型、地面材质与状态、背景环境物、光位与光质、空气介质（尘/雾/雨） |
| 不管 | 角色、动作、镜头运动（归动作卡与镜头卡） |
| 不管 | 画风线条与色彩体系（归画风卡）——只写「物理上有什么、光怎么落」 |
| 与画风卡的分界 | 画风卡答「怎么画」，场景卡答「在哪打」；两者五元组正交 |

### 0.2 要接管的动作卡劣势（来自 Circle4/5 实测）

| 项 | 数据 | 场景卡怎么管 |
| --- | --- | --- |
| 扬尘未出 | 0/6（Circle4 六轮） | 地面给「表层细干土」，让「砸地扬尘」有物理来源 |
| 背景与风格轮间随机 | 0/3 一致（Circle5） | 锁死场地与环境物，把随机背景变成可控置景 |
| 击飞位移不可读 | 部分轮次 | 地面加纵向纹理（车道辙/板缝），给后飞距离一把尺子 |

不进场景卡：格挡形态、掌/拳套、拨开方向——那些是动作卡与风格采样的事。

### 0.3 三个验证问题（本轮要回答的）

| # | 问题 | 判据 |
| --- | --- | --- |
| 1 | 场景是否被兑现 | 场地/地面/光线三项在成片中能否逐项指认 |
| 2 | 场景会不会吃掉动作 | 五帧动作链（迎拳→格挡→拨开→推掌→击飞）是否仍在；与 Circle5 dual-4 对照 |
| 3 | 场景是否稳定背景 | 同 prompt 至少 2 条，比较场地/环境物是否一致（Circle5 基线 0/3） |

### 0.4 对照组（零成本）

Circle4 六条无辅助卡视频＝「无场景卡」基线：背景随机、扬尘 0/6。本轮不与它比美观，只比「背景是否被锁住」与「扬尘是否出现」。

## 2 · 三条结论（本轮核心）

1. **辅助卡范式在空间维度同样成立**：场景卡五项要素 2/2 逐项可指认，动作链 2/2 完整，无风格污染（对比 Circle5 首条被带出拳套影棚）。
2. **扬尘从 0/6 救到 2/2**：动作卡写「触地扬尘」却没写地面是什么，场景卡补上「表层 2–3 mm 细干土」，物质前提一到位就出尘。这是「辅助卡掩盖基础卡劣势」的标准样本。
3. **场景卡管不住构图与攻守可读性**：不写运镜＝固定机位，pair-1 主体半身出画、3/3 接触段两人同时举手分不出攻守；这两项恰是 Circle5 镜头卡已解决的，须叠卡。
4. **辅助卡的每个词都会带进它的语义邻域**：竹林卡写「石板微磨光」「苔面湿润」，模型就给了反光的湿石板，扬尘随之归零。与 Circle5「镜头参数带出拳套影棚」同源，但更隐蔽——数字不生效只是浪费，形容词会改写物理。
5. **换场景卡不动动作**：三张一绑，动作层 3/3 全过（推掌、击飞逐步成立，竹林条腾空横飞最强），形态层 3/3 同败（拨开 0/3）。场景卡是可替换的空间件。
