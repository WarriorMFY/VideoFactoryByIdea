## 一句话

把"抠图"升级成一套**像素锚点流水线**（抠图 → 合成首帧 → 打分 → 首尾帧配对 → 生成视频），并用实测数字确认了：首帧就是当前通道里最硬的像素约束。

## 结论：哪些容易对齐，哪些不容易

**容易对齐（实测能钉住）**

- **主体身份**：透明底机甲合成后重新抠图，`mask_iou` 0.958–0.966，轮廓几乎没漂。
- **构图／机位／光色**：以首帧为 0 秒约束生成 5 秒视频后，机甲位置、大小、两侧街灯与树的相对关系、冷青灰雾色调全部守住。
- **整体氛围与次级运动**：雨、雾、贴地雾、积水涟漪由模型自己补，方向与浓度可控。
- **单镜头内的有限动作**：炮塔 3 度、炮管 2 度、指示灯两次明灭，这类"小幅度、有重量感"的指令模型接得住。

**不容易对齐（实测会漂或直接失败）**

- **细杆／线状物**：街灯抠图覆盖率 0.3%，模型对"显眼整体"有显著度偏见，细结构直接丢。
- **人形剪影**：防暴警能抠出来，但背景同类人影留半透明"幻影"，主体与背景同色时边界不可判定。
- **半透明物**：烟柱在 `u2net` 下整块保留、在 `isnet` 下被切掉，同一素材两个模型给出相反答案——雾、烟、纱这类东西没有稳定口径。
- **边缘质量**：抠图边缘的亮色残留会在新背景上变成白边，`halo_ratio` 首版 1.445，必须靠 alpha 内缩 + 边光降档才能压到 1.074。
- **跨帧的运动轨迹**：首帧能锁"起点长什么样"，锁不住"往哪走、走多快"，这要等尾帧位。

## 修正后的判断（本轮最重要的一条）

**"没有尾帧位"的旧结论已按用户要求作废**，不再作为规划前提。当前按"尾帧位迟早会有"设计：`pair` 已经把"切镜头 + 首尾帧 + 光流量"建成可复用的锚点对，通道一开直接接。

## 待优化

1. **色彩锚**没做：主色板、色温、材质贴图缺位，现在色彩只靠合成时那一次亮度对齐。
2. **语义距离**用 ORB 近似（0.27），缺 CLIP/DINO 这类真嵌入；身份一致性判据偏弱。
3. **多主体仍需人工写框**；SAM 点选式分割没装，自动识别没做。
4. **`edge_iou` 不能单独定生死**：alpha 内缩让轮廓小 1–2px，边缘比对天然吃亏，需换更稳的轮廓度量。
5. **锚点预算规则尚未实测**：硬锚/软锚、冲突优先级（身份 > 构图 > 时序 > 色彩）目前只是文档，没跑过真实冲突用例。
6. **合规**：素材水印保留、来源登记还没落成卡的元数据字段。
