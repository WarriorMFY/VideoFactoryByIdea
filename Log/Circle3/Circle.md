## 2 · 与模型的对齐度

| 容易对齐 | 依据 |
| --- | --- |
| 段落级结果：对峙 → 近身 → 倒地 → 收招 | 抽帧导航可见，整体序列在 |
| 起手与末态（持盾前冲、B 倒地） | 首尾段与卡大致吻合 |

| 不容易对齐 | 依据 | 性质 |
| --- | --- | --- |
| 接触类事件：盾撞胸肩、剑尖贯入咽喉 | 全片无刺入、无拔出；剑在腰后或高举过头 | 最重一处，持续 0.75s 以上 |
| 「同一拍」的同步 | 盾撞 / 换架 / 刺喉被拆成数段，中间有 1.25s 僵持 | 节奏层失效 |
| 发力链与左右手分配 | 「左肩后撤、右肩前送」看不出；前伸的是徒手托下巴 | 部件语义丢失 |
| 卡外内容抑制 | B 手里多出一柄短刃 | 模型按对决常识补全 |
| 整卡直塞的执行精度 | 可能被当场景描述而非逐帧指令（推测，未跑对照验证） | 输入形式风险 |

## 3 · 硬结论

1. **通道差异大于改卡收益。** 同一张卡、同一份原文：Seedance2.0-Mini 90%，H3 60%。先问「哪个通道认这张卡」，再问「卡怎么改」。
2. **整卡 markdown 直塞会掉精度。** 至少在这条 5s 单镜头里，模型把表格结构读成了场景说明。要验证需另跑「只送三帧主表」对照，本轮未跑。
3. **例外入库要留痕，不要美化。** 准入四条缺三条、运行时指纹缺 4 项，全部如实写空，不补写、不倒推。
4. **逐字链只能闭合到本地。** 本轮推进到 HTTP body 序列化并落盘可复现请求体；服务端回读接口不存在，画布输入 `403 TOKEN_MISSION` 读不回来。
5. **人工验收＝用户裁定，不由助理复核。** 「90% / 60%」两个数字不在任何截图里，如实标注为不可核验。
