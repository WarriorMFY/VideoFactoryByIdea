## 第一条 T1-人工核

三个要素全部到位，无一缺失：

1. **单独一个总控制台**：有，居中最高的弧形台，台面一整排显示屏，正面挂牌「总控制台」。
2. **下方多排多列子控制台**：有，前景 4 排 × 每排 4 列（左右各半，中轴留走道），每席配双屏、桌面电话、黑色办公椅。
3. **只有场地没有人**：成立，全画面无人物；椅子全空。

**错的地方（不是缺，是加）**：模型自作主张烧进三处硬文字——

- 顶部机关名牌「航空发射总控中心」+ 卫星 logo（把提示词的「现场」改写成了「中心」）；
- 总控台正面「总控制台」；
- 大屏区「发射倒计时 T-00:30:00」与两侧表格里的类汉字小字（伪中文，不可读）。

**边界点**：提示词没写「不要文字」时，本通道会给场地补招牌与大屏读数。作为场地锚，硬字烧进像素就无法改语言/改读数，后续分镜若出现不同机位的同一块屏会对不上。要干净场地需在提示词加否定句，但本圈用户令「提示词严格不动」，故不改不重跑。

## 结论

- 一句话：提示词原样一次过，三要素（总控台 1 个 / 下方多排多列 / 无人）全对齐，成本 12.28，唯一偏差是模型自加的招牌与倒计时硬文字。
- 对齐容易：静态空景、居中主体＋阵列背景，本通道一次到位，连椅子/电话这种小件都补齐。
- 对齐不容易：**文字**——提示词不提也会自己加，且喜欢把场景名升级成机构全名（现场→中心）。
- 待优化：需要纯净场地时，得在提示词里显式否定文字；或改走第二档通道（无镜像倾向，文字倾向未测）。

## 第四条 T4-人工核

要素核对：

1. **反打机位（本轮新增项）**：**一次到位**。前景就是主控台的台面——键盘、操纵杆、拨键面板、屏幕背面全朝向镜头；越过主控台是铺到远处的大片子控台阵列；再远是整墙大屏（世界地图 / 发射实景 / 雷达盘 / 地球）。空间层级（主→子→大屏）完全正确。
2. **单独一个总控制台**：成立。前景只有一条主控台，且因为是背后机位，它以「一条台 + 一只空椅」的形态呈现，未被风格词冲成排台。
3. **下方多排多列子控制台**：成立，密度四条之最——中景横向数十列，纵向多排，每席多屏。
4. **只有场地没有人**：成立。画面底部中央只露一把空椅的椅背，全图无人物。
5. **NASA朋克风格**：成立且最像——裸露钢梁顶、二层钢架走道、暗蓝屏幕光 + 琥珀色拨键指示灯（老式面板味）。
6. **禁止组织Logo**：成立。无 NASA 徽标、无旗帜、无机构名牌。

**偏差**：子控台阵列密度过度，中景几十上百块屏挤成光点墙，已不太像「可坐人的席位」；做游戏化场景尚可，做可执行的分镜场地（后续要往里放人）则需要更稀的排布。

**连带**：本次因机位转向，窗户/外景根本没进画（被大屏墙挡住），所以 T3 的「透窗洗白」问题自动消失——**反打机位顺带把封闭暗舱感找回来了**。

## 结论（四条合看）

- 一句话：**T4 是四条里最好的一张**——三要素全中 + 无 Logo + 机位最具体，且反打机位顺带把封闭暗舱感找回来了；瑕疵是中景子控台密到不像能坐人的席位。
- 机位句是本轮最大的杠杆：「镜头从主控制台看向子控制台」一句话同时解决了三件事——把主控台固定为单体（只能是一条台）、把子控制台推到多排多列的阵列、把挂旗的墙挡在大屏后方不出现。
- 对齐容易：风格词、否定 Logo、机位叙述都是一点就灵，没有一次需要重试；无人也四条守得住。
- 对齐不容易：「**单独一个**」的体量语义靠自身叙述不稳（T2 丢失），需要靠机位或体量描述夹住；文字仍是默认产物，只能否定不能预控。
- 通道行为：同组同档 16:9·1k 出了**两种像素**（1672×941 仅 T1，其余 1360×768）；耗时 54–143s、实扣 10.93–12.28，波动大于 SKILL 旧记录。
- 待优化：① 子控台密度需限定（如「每排四到五列、留出坐人空间」）；② 要「通窗观景 + 暗舱」共存需另试；③ 四条总花销 45.76，建议本圈内不再加深同组样本，转入视频试跑。

# 第四段 · 验证：i2i 能否一次只出 1 张

用户问「当前 i2i 不能一次只生成一张图吗，其他不动」。查 + 实测，其余全同一套（锚 T4 / V2 提示词 / 16:9）。

## 先查

| 事实 | 出处 |
| --- | --- |
| 节点 `72:value` 为 `PrimitiveInt`，`fieldType=INT`，`fieldValue="2"`，`control_after_generate=fixed` | `runninghub_app.py --info 2114585366186516481`（不扣积分） |
| `runninghub_app.py` 把 `--node` 的值一律当**字符串**写进 `nodeInfoList[].fieldValue` | `parse_node_arg()` / `apply_modifications()` |
| 历史记录：传 1 仍出 2 张，但未分清是「节点被忽略」还是「类型不对」 | `flux3-edit/reference/nodes.md` 待验第 1 条 |

## 再实测（V3-n1，`--n 1`，其余与 V2 完全一致）

- 任务 `2125516450771980290`，**实扣 25.33**，149s。
- **实际出图：2 张**，`edit.py` 自己也报了「请求 n=1，实际出 2 张」。

## 结论

- **不能。当前通道不支持一次只出 1 张**：`72:value=1` 已提交但无效，仍固定出 2 张，且按提交计费、不因 n=1 减半（25.33 vs n=2 的 23.8/46.07，同量级）。
- 三条 i2i 账并排看，**价格与 n 无关**，在 23.8–46.07 间浮动：

| 条 | 请求 n | 实出 | 实扣 | 耗时 |
| --- | --- | --- | --- | --- |
| V1-人物构成 | 2 | 2 | 23.8 | 140s |
| V2-人物多样 | 2 | 2 | 46.07 | 271s |
| V3-n1 | **1** | **2** | 25.33 | 149s |

- 两种可能未区分（未花钱去证）：① 工作流内部出图数写死，`72:value` 接在别的输入上；② API 对 INT 节点要 JSON 数字，字符串 `"1"` 被静默丢弃回默认 2。要区分需改 `runninghub_app.py` 对 INT 类型传数字（Skill 只读，本圈未改）。
- 当前现实：想要 1 张只能“买两张用一张”，或换支持数量的通道。

## 顺带的意外（V3 构图）

同一段提示词第三次跑，构图与前两条完全不同：8 人**正面站成一排**面向镜头，主控台前只剩一把空椅。多样性拉满了（白发老者 / 黑人男性 / 亚裔男女 / 不同体型），但**站位全错**：无人坐/站在子控台前，全挤到主控台后方。另出现胸牌小字（未违“禁止 logo”，但仍是文字）。度量：ssim 0.4701 / 0.4172，sharp 472.6 / 493.2。
- 教训：同 prompt 第三次重跑不是“重采样”，而是**换了一个构图解**；单张结果不能当作风格基线，只能当作样本。

# 第五段 · 文生视频：倒计时到点火

## 提示词（用户原话，逐字不改）

```
控制室内，全场安静，只有“倒计时：5,4,3..”的广播声音，所有工程师原地起立，神情紧张，都不说话，注视眼前，在广播喊到“1”的瞬间，总工程师的手按下了点火按钮。
```

## 中间过程

  - 任务 `2125521787986071554`，**实扣 14.28**，84s。
  - 产物：`t2v/runs/V1-倒计时点火/out.mp4`（探针自动把 MOV 容器修成 MP4）。

## 度量

| 项 | 值 | 判读 |
| --- | --- | --- |
| 尺寸 | 960×544 | 16:9 的 480P，无黑边（左/右 0px） |
| 时长 | 实测 5.167s（请求 5.0s，偏 +0.167s） | 合格（模型侧 5s 硬下限，Circle15 已知） |
| 帧率 | 24fps / 124 帧 | 正常 |
| 运动 `motion_max` | 58.05（格 5，中心） | 档位「大」——起立动作本身就大 |
| 分区运动 | 1:49.4 / 2:48.5 / 3:36.3 / 4:55.2 / **5:58.1** / 6:39.8 / 7:44.4 / 8:46.0 / 9:48.0 | 全画面普遍在动，中心最强（人物本体）；格 3/6 偏弱（右上、右中背景） |

## 人工核（抽帧 2fps，10 帧看完）

**做到了的：**

1. 控制室内（但见下方“场面跑偏”）。
2. 全场安静、都不说话：无人张嘴，无误读的交流动作。
3. 所有工程师原地起立：0–1s 坐姿，1–2s 集体站起，动作齐、幅度对。
4. 神情紧张：全员嘴唇抿紧、目光前视，表情到位且全程稳定。
5. 注视眼前：镜头为侧向斜拍一排人，视线统一向前。
6. 末帧（≈4.5s）确实有一只手向左上方伸出按向墙上装置。

**没做到 / 撞边界的：**

1. **「广播声音」只能变成硬字幕**：本条 mp4 **无音轨**（ffmpeg 报 audio:0KiB），声音要求在这条通道上无解。模型自选了替代方案——把两句台词烧成字幕：前半「倒计时：5,4,3..」，后半「在广播喊到“1”」，反而把时间结构标出来了。
2. **「总工程师的手按下点火按钮」降级**：按下的是墙角一个不明开关，不是主控台上的点火钮；按的人也不是那个“总工程师”，且发生在末尾约 0.5s 内，没形成「喊到 1 的瞬间同步按下」的节拍。
3. **场面完全跑偏**：场景是普通办公室/机房（白吊顶方格灯、白墙、办公桌），与前四条 NASApunk 总控室毫无关系；人物是白衬衫蓝领带、蓝色挂绳工牌，像呼叫中心而非发射场；全员亚洲男性，**无女性**。纯 t2v 无锚，自己发明了一个场景。
4. **5s 节拍偏紧**：起立在 2s 内完成，3–4.5s 基本是站立待机，最后 0.5s 才伸手。想要「倒计时逐秒张力→1 的瞬间按下」，节奏需要更长档位（ 9–15s）。

## 结论（文生视频）

- 一句话：事件序列 4/5 拍完成（安静→起立→紧张注视→伸手），唯一核心动作「喊到 1 的瞬间按下点火钮」降级成末尾 0.5s 的随手按开关；而场景、人物与前四条完全断链。
- 可行：动作类叙述（起立、转向、伸手）模型能按顺序做出，且全镜无跳变；紧张表情稳定不漂。
- 不可行：① **声音**——本通道无音轨，广播/警报声一律只能用字幕或后期配；② **场景一致性**——t2v 无锚就会自造场景，指望它接上前面的 NASApunk 总控室不现实；③ **时间点同步**（“在喊到 1 的瞬间”）在 5s 内无法成立。
- 下一步建议：要吃前面的场地与人，必须转 i2v（拿 T4 或 V2 的 out 作首帧）；声音另行配音。
