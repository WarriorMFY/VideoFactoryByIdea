### 三条判据

**一、单帧判据看「同步」列，不看「武器接触」里的动作词。** K2 的「同步=剑尖对齐甲状软骨下缘」是这一帧的落点；「武器接触=剑尖刺入咽喉」描述的是动作意图，不是本帧终态。前两轮 FAIL 全部源于违反此条。

**二、视频必须通看全片。** 9 帧拼图的采样间隔 0.57 秒，盾撞与刺入都是 0.1–0.2 秒级事件，必然落在两帧之间。稀疏抽帧只能定位段落，不能判定动作发生与否。

**三、L2 要做两遍：先七类矛盾，再武术七问。** v1 的问题全部逃过了第一遍的表格检查——格子都填满了，但格子之间互相打架（盾心对盾缘、剑刃一百厘米却「没入至护手」），或者互相自洽却发不出力（屈肘加前脚落定却要求刺穿）。前者靠串句和算式能查，后者只能靠「这一下打不打得了」的直觉。

### 改卡的边界

第 3 轮误判 FAIL 后，曾将 K2 的「刺入」改为「抵住」以迎合模型输出，被用户当场纠正并撤销：「处决动作不刺入干啥」。

| 情形 | 是否改卡 |
| --- | --- |
| 卡自身逻辑错误（方向矛盾、几何不自洽、缺因果、数字对不上） | 改 |
| 模型画不出卡描述的动作 | 不改 |

卡是标准，模型是执行者。模型做不到，记通道限制，不记卡错；为通过验证而降低动作标准，性质上等于伪造证据。

### 失败判据（用户定，两条）

**一、链路顺序：卡片 → 图片先对齐，对齐之后才允许 卡片 → 视频。**

本循环反了：L3 从未真正对齐，就把 L4「通看全片通过」当成整轮通过。L3 未对齐的具体表现：

| 表现 | 出处 |
| --- | --- |
| 同套键值 Prompt 第 4 轮出图注、第 6 轮出写实，图注行为不稳定 | 阶段 9 / 11 |
| v3 原文三次被 1501 内容安全审核挡回，正式 L3 从未跑通 | 12.3 |
| 脱敏版降了落点判据（「入点」→「指向」），拿降标准的图判没降标准的卡 | 12.4 |
| 把图注框里模型抄写的 Prompt 当成画面执行证据 | 12.4 |
| v3 卡自身几何没算通，且跳过 L2 直接送验 | 12.2 / 12.4 |

图片关没有稳定、可核验的对齐，视频关的结论就没有前提。**下一轮先建立「卡片 → 图片」的对齐，对齐不成立不得进「卡片 → 视频」**；两条链路分开建，不并行、不互相背书。

**二、卡片是最终真相，也是唯一真相。**

现在无法确认 LLM 是否真的按卡片原文发送。送验链路上每一环都可能改动原卡，而现有校验只覆盖到落盘文件：

| 环节 | 本轮出现过的改动 | 是否可核验 |
| --- | --- | --- |
| 卡片原文 | — | 是 · 唯一基准 |
| Prompt 落盘 | 第 2 轮「助理误报已改 Prompt，实际未落盘」 | `verify_prompt.py` 可验卡 ↔ 文件 |
| 实际送出的请求 | 脱敏替换、节点覆盖、`run_l3.py` 加 `18:prompt=` 包装前缀 | **否** · 落盘文件 ≠ 线上请求 |
| 模型执行 | v2 把 90° 屈肘擅改直臂、三条手臂、落点下移 | 否 |
| 图注 | 模型抄写 Prompt，被当成执行证据 | 否 |
| 助理判读 | 拿降了标准的图判没降标准的卡 | 否 |

因此：任何中间产物不得改写卡片，也不得反过来作为判定卡片的依据；图片、视频、图注、判读只能与卡片原文比对，不能替代它。要消除「不确定」，下一轮需把逐字校验延伸到实际送出的请求（卡片 → 落盘 → 线上请求三方比对），否则「逐字验收」仍只是一句声称。
