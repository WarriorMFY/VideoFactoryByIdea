# 首尾帧工作流 · 最小闭环搭建清单

> 目标：在 RunningHub 上拥有一条**自己的**「首帧 + 尾帧 → 视频」工作流，用 API 一键调用，不再依赖市场里别人随时会关掉的应用。
> 取证时间：2026-11-19 22:30；账号 `apiType=NORMAL`、`remainPoint=18688`、`remainCoins=1000`。

---

## 一、先记住三条铁律

1. **`workflowId ≠ webappId`。** 我们跑成功的是「AI 应用」（`2103693788333039617`），它背后那条工作流的 ID 拿不到——实测拿 appId 调 `getJsonApiFormat` 返回 `380 WORKFLOW_NOT_EXISTS`。自建必须有自己的 `workflowId`。
2. **API 不能"创建"工作流，但可以"绕过工作台直接跑自己的图"。**（2026-11-19 实测修正，见 §九）`workflowId` 必填但只需给一个**存在的**值占位，真正的图用 `workflow` 字段整份塞进去，平台会覆盖执行。
3. **图位靠 `nodeId + fieldName` 定位，不靠名字猜。** 每个工作流导出一次 JSON 看 `inputs`，就知道该改哪个节点。

---

## 二、完整链路（5 步，全部实测过的端点）

| 步 | 动作 | 端点 | 关键字段 |
| --- | --- | --- | --- |
| ① | 传素材 | `POST /task/openapi/upload`（multipart） | `apiKey`、`file`、`fileType=input` → 回 `data.fileName`（形如 `api/xxx.png`） |
| ② | 提交任务 | `POST /task/openapi/create` | `apiKey`、`workflowId`、`nodeInfoList[{nodeId,fieldName,fieldValue}]`；可选 `instanceType`、`webhookUrl`、`workflow`（整图 JSON，覆盖 workflowId） |
| ③ | 查状态 | `POST /task/openapi/outputs` | `apiKey`、`taskId` → `code=0` 完成；`804` 运行中；`813` 排队；`805` 失败（`failedReason.node_name` + `exception_message` + `traceback`） |
| ④ | 取结果 | 同上，`data[].fileUrl` | 直接下载 |
| ⑤ | 兜底 | `POST /task/openapi/cancel` | 跑飞了能止损 |

**补充能力**：`POST /api/openapi/getJsonApiFormat`（`apiKey` + `workflowId`）能取回任意**公开工作流**的图 JSON。实测用文档示例工作流 `1904136902449209346` 返回 `code=0` 和完整 `prompt`（KSampler / CheckpointLoaderSimple / VAEDecode 那套）——**这意味着"抄一条现成的图"这条路是通的**。

---

## 三、workflowId 从哪来

三条来源，按省事程度排：

1. **自己的工作台**：网页里新建/打开工作流，URL 形如 `https://www.runninghub.cn/workflow/<id>`，这段数字就是 `workflowId`。
2. **导出 api.json**：工作流编辑器右上角「导出 API 格式」，得到 `api.json`——这是改节点用的底稿（`{nodeId: {class_type, inputs}}`）。
3. **抄公开工作流**：`getJsonApiFormat` 读到别人的 JSON，粘进自己账号新建的工作流里，再导出自己的 `workflowId`。

## 四、最小图结构（两种实现，选一个）

### 方案 A：抄现成（最稳）

平台已经装好了一套首尾帧链路（我们跑成功的那条 app 就是证据，405 秒出 5s 成片）。做法：
1. 找到那条工作流的公开版本（作者若公开，`getJsonApiFormat` 能取）；
2. 把 JSON 粘进自己账号的新工作流；
3. 只改三样：两个 `LoadImage` 的 `image`、一个提示词、宽高。

**风险**：作者不一定公开。公开版找不到就走方案 B。

### 方案 B：自己搭（4~6 个节点）

```
LoadImage(首帧) ┐
LoadImage(尾帧) ├→ 首尾帧条件节点 → KSampler → VAEDecode → SaveVideo
文本编码(提示词)┘         ↑
                      尺寸/帧数节点
```

需要确认的四个部件：

| 部件 | 要查什么 | 判断标准 |
| --- | --- | --- |
| 模型加载 | 平台是否已装 Wan2.2 / LTXV / MiniMax H3 的 unet + vae + clip | 节点下拉里能搜到、且不用自己传模型 |
| 首尾帧条件节点 | 有没有吃两张图的条件编码（如首尾帧 video 节点） | `inputs` 里出现两个 image 入口 |
| 采样 | KSampler / 专用采样器 + 步数（现成 app 用 8 步） | 能跑 8 步出片即够 |
| 输出 | `SaveVideo`（或 CreateVideo+SaveVideo） | 没有它，`outputs` 取不到 `fileUrl` |

**关键判断**：既然市场那条 app 能在平台上 405 秒跑完，说明模型和节点**平台侧都已装好**——自建不需要装环境，只需要把图连对。

## 五、参数与坑（都是踩过的）

| 坑 | 实情 |
| --- | --- |
| 尺寸节点顺序不保证 | 现成 app `29=1280`、`30=720` 出的是 720×1280（竖屏）。**自建时导出 JSON 后必须核对哪个是高**，别按名字猜 |
| 图位字段名 | `LoadImage` 用 `image`；上传返回的 `api/xxx.png` 原样塞进去，不要拼域名 |
| 单文件 30MB 上限 | 超过就传公网直链 URL 给加载节点（官方建议走 OSS/S3 直链） |
| 输出必须落到 `save/` 类节点 | 只在预览节点出图，`outputs` 拿不到文件 |
| 时长不由"秒"决定 | 多数自建链路是**帧数 × 帧率**，不是 5s/8s 档位 |
| 排队 | 现成 app 一条 5s 跑了 405 秒；自建走 GPU 实例，`default` 24G / `plus` 48G / `ultra` 84G |

## 九、补记：绕开工作台的直跑法（2026-11-19 实测）

**一句话**：把整份图 JSON 放进 `workflow` 字段，`workflowId` 随便给一个存在的图当占位，任务就会按你的图跑。

```
POST /task/openapi/create
{ "apiKey": "...", "workflowId": "1904136902449209346",   // 占位，必须存在
  "workflow": "<整份 24 节点 JSON 的字符串>",
  "nodeInfoList": [{nodeId:"205",fieldName:"image",fieldValue:"api/xxx.png"}, ...] }
```

- 不传 `workflowId` → `301 must not be null`；`workflowId` 给了不存在的值 → `380`。所以占位必须真实存在。
- 实测任务 `2123424206111858689`：`code=0`，102 秒出片，输出文件名带我们图的 `AnimateDiff` 前缀，**证明跑的是塞进去的图**。
- 模板：`wf_template_firstlast_1967630045374287873.json`（来自公开帖 `workflow/1967630045374287873`，Wan2.2-VACE-Fun 首尾帧，24 节点）。
- **图位方向陷阱**：模板里 `204` 标题写 `Start`、`205` 标题写 `End`，但连线是 `199(←205)→start_image`、`200(←204)→end_image`，**实际 205 是首帧、204 是尾帧**。改方向只需互换这两张图。
- 直跑脚本：`Log/Circle21/run_workflow_direct.py`。
