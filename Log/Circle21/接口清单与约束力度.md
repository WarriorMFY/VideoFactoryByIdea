# RunningHub 接口盘点与「约束力度」分级

> Circle21 · 2026-11-19 · 数据来源：`data/capabilities.json`（420 端点，实时 `--list` 校验一致）+ 官方文档索引 `llms.txt`（415 篇）
> 一句话：**RunningHub 现在有 48 种任务、420 个标准接口；能给"像素级约束"的只有 5 种（首帧、首尾帧、动作驱动、视频续写、视频编辑）；能给你"绝对确定"的只有 4 种后期算法接口（放大/补帧/提帧率/降噪）。其余全是语义级。**

## 二、约束力度分档（这是本报告的核心）

「约束力度」= 你能用像素把模型"钉"住多少。不看模型多大，只看**接口给了你什么输入位**。

| 档 | 名称 | 接口给的锚 | 模型管得住 | 模型管不住 | 可复现度 |
| --- | --- | --- | --- | --- | --- |
| **C0** | 语义级 | 只有一段文字 | 发生什么、先后顺序、"别动"类否定句 | 长什么样、第几秒、多大比例 | **0**：同 prompt 两次两条不同片 |
| **C1** | 参考级 | 1–14 张参考图（身份/风格/道具） | 人脸、服装、道具的"身份" | 具体构图与位置、背景像素 | 低：识别度像，但画面重排 |
| **C2** | 单帧像素级 | 首帧 1 张（`firstImageUrl`/`imageUrl`） | 第 0 帧的**像素级**构图 | 第 1 帧以后的动作与背景 | 中：首帧 NCC≈0.956，随后漂移 |
| **C3** | 双帧像素级 | 首帧 + 尾帧（两条硬锚） | 0 秒与末秒的像素构图，中间由模型补 | 中间过程怎么走、走多快 | 中高：两端钉住，中段每次不同 |
| **C4** | 结构/轨迹级 | 原片（视频）作为驱动或底片 | 动作轨迹、机位运动、镜头结构 | 材质重绘的细节像素 | 中：骨架一致，肉重画 |
| **C5** | 确定性像素级 | 原片（无模型采样） | 全部像素（放大/补帧/降噪） | 不能新增内容 | **1.0**：同一输入重跑输出唯一 |

**判档口诀**：看接口的图位是"几帧"而不是"几张图"。一帧（首）→C2，两帧（首+尾）→C3，多张（参考）→C1，一条视频→C4。

## 三、逐接口卡（按档位归位）

### C0 语义级（只能"说给它听"）

| 接口 | 数量 | 参数（真名） | 官方说明要点 |
| --- | --- | --- | --- |
| `text-to-video`（文生视频） | 60（57 个纯文本） | `prompt`、`aspectRatio`、`duration`、`resolution` | 官方描述全是"cinematic realism / coherent motion"这类，没有一个帧位 |
| `text-to-image`（文生图） | 42 | `prompt`、`aspectRatio`、`resolution` | 同上，纯文本 |
| `text-to-speech`（TTS） | 10 | `text`、`voiceId`、`speed` | 文字→声波，无语义外约束 |
| `music-generation`（音乐） | 19（17 纯文本） | `prompt`/`lyrics`、`style` | — |

> 实测（Circle11/12：同 prompt 两次，切点命中 0/6，数值约束 0 落点）与官方描述一致：**文字只约束"语义槽位"，不约束像素**。

### C1 参考级（能锁"是谁"，锁不住"在哪"）

| 接口 | 数量 | 关键参数 | 能力 |
| --- | --- | --- | --- |
| `reference-to-video`（参考生视频） | 25（22 带媒体位） | `imageUrls`（最多 7）、可选 `videoUrl`、`keepOriginalSound` | 官方："Identity Lock"——多视角参考锁人物/道具身份 |
| `multimodal-video`（多模态生视频） | 12 | `imageUrls`×9 + `videoUrls`×3 + `audioUrls`×3 + `generateAudio` + `returnLastFrame` | 图+视频+音频混合输入；`returnLastFrame` 可回吐尾帧（重要：能造出自己的尾帧） |
| `image-to-image`（图生图/编辑） | 35 | `imageUrls` 最多 **10–14** 张、`prompt` | 多图融合改图；仍是重排，不是逐像素保留 |
| `image-to-3D` / `multi-image-to-3D` | 8 / 6 | `imageUrl`；前/后/左/右四视图 | 单图或多视图→网格 |

### C2 单帧像素级（钉住第 0 帧）

| 接口 | 数量 | 关键参数 | 实测 |
| --- | --- | --- | --- |
| `image-to-video` 中"只有首帧位"的 | **37** | `imageUrl` / `firstImageUrl` + `prompt` + `duration` + `resolution` | 首帧对源图 **NCC≈0.956**；第 1 帧起背景即被模型重画 |

> **特别注意**：`image-to-video` 共 **72** 个，但**只有 37 个是"纯首帧"**；其余 23 个是首尾双锚（下一档），5 个是多图参考（属 C1），2 个纯文本。选接口时别被任务名骗了。

### C3 双帧像素级（两头钉死，中间补）

| 接口 | 数量 | 关键参数 | 说明 |
| --- | --- | --- | --- |
| `start-end-to-video`（首尾帧生视频） | **10** | `firstImageUrl` + `lastImageUrl`（都必填）+ `prompt` + `duration`（多为 5/8/10 秒档） | 官方：`kling-video-o1/start-to-end`——"同时给出起点与终点的视觉状态，模型用时空推理补出中间"，明确写"eliminates the unpredictability of AI video endings"（消除结尾不可控） |
| `image-to-video` 内带尾帧位的 | **23** | `firstFrameUrl` + `lastFrameUrl`（如 MiniMax H3 Max、Veo 3.1、Wan 2.2、PixVerse） | 与上一档同一族模型，只是开放了尾部位 |
| `video-transition`（视频转场） | 3 | `firstImageUrl` + `endImageUrl` | 两图之间做转场过渡片段 |

覆盖这 10 个首尾帧接口的品牌：Vidu q2/q3（5 个）、Kling o1、Veo 3.1 fast/pro/lite、Wan 2.2、MiniMax H3 Max。
**这是当前唯一能同时锁"开头像素"和"结尾像素"的生成接口。**

#### C3 实测（2026-11-19 22:09，个人号应用通道）

- 通道：webapp `2103693788333039617`（Wan2.2 首尾帧，开源）；节点 `48:image`=起点锚、`49:image`=掠过锚、`34:prompt`、`29/30`=高/宽。
- 任务 `2123416532494278658`，耗时 405s，出 720×1280 / 81 帧 / 5s。
- 度量（基准=`锚图中心裁 9:16` 后 resize 到出片尺寸）：

| 对比 | NCC | SSIM |
| --- | --- | --- |
| 首帧 × 起点锚 | **0.9303** | **0.8011** |
| 末帧 × 掠过锚 | **0.7390** | **0.7578** |
| 首帧 × 掠过锚（交叉） | 0.2172 | 0.3314 |
| 末帧 × 起点锚（交叉） | 0.1878 | 0.3436 |

- 结论 1：**两端确实被钉住了**，且顺序对（48=首帧、49=尾帧），交叉值 0.19–0.22 说明没有错位。
- 结论 2：**尾帧比首帧松**（0.74 vs 0.93）——尾部只是"大致这构图"，不是同一像素。
- 结论 3：**中段仍是脑补**。strip 里灯塔从镜头外"生长"出来、三人从山坡滑到海面，模型把尾帧里的灯塔提前放进了画面。首尾双锚管两头，不管过程。
- 结论 4：本次宽高参数搞反（`29` 实为高、`30` 为宽），出成竖屏，2.48:1 的锚图被裁成 9:16；改横幅重跑数值应更高。

### C4 结构/轨迹级（拿原片当骨架）

| 接口 | 数量 | 关键参数 | 模型管住什么 | 官方原话 |
| --- | --- | --- | --- | --- |
| `motion-control`（动作控制） | 5 | `imageUrl`（角色图）+ `videoUrl`（驱动视频）+ `prompt`（可选） | 把驱动视频里的**舞步、手势、运动轨迹**搬到角色身上；骨架级复刻 | "Upload a character image and driving video to make the character accurately replicate dances, gestures, or movement trajectories"（3D 时空关节注意力 + 思维链） |
| `video-extend`（视频续写/延长） | 7 | `videoUrl` + `prompt` + `negativePrompt` + `seed` + 可选 `audioUrl` | 接着**你原片的真实尾态**往下长，像素连续性最好；内容是新的 | Wan 2.7：延续现有片段，出 720P/1080P，最长 15 秒 |
| `video-edit`（视频编辑/重绘） | 10 | `videoUrl`（必填）+ `imageUrls`（最多 7）+ `prompt` + `keepOriginalSound` | **保留原片运动与结构**，只换对象/场景/风格；不是逐像素保留 | Kling O3 Pro："preserving original motion and structure"，Pro 支持最多 4 张参考图 |
| `video-to-video` / `draft-enhance` / `video-continuation` | 3 | `videoUrl` | 原片做草稿再精修/续帧 | Flux 3 video |
| `lip-sync-video` + `digital-human` | 3 + 2 | `audioUrl`/`audioId` + `faceId`/`sessionId`，`soundStartTime/EndTime/InsertTime` | 口型与音轨对齐（可精确到插入时刻） | Kling lip-sync / AI Avatar |

### C5 确定性像素级（算法，不采样）

| 接口 | 数量 | 参数 | 输出是否唯一 |
| --- | --- | --- | --- |
| `video-upscale` | 5 | `videoUrl` | 是（同一输入必得同一输出） |
| `video-frame-interpolation` | 1 | `videoUrl` + `outputWidth/Height` + `outputFrameRate` | 是 |
| `video-fps-increase` | 1 | `videoUrl` | 是 |
| `video-denoise` | 1 | `videoUrl` | 是 |
| `image-upscale` | 13 | `imageUrl` + 人脸增强三参 | 是 |
| `video-subtitle-erase`（字幕擦除） | 2 | `videoUrl` | 是 |

> 这一档正好对上本仓库的判据：**同一输入重跑是否唯一 → 唯一归编辑（editing），不唯一归生成（generation）**。所以 C5 可以放心用于"成片级"收尾，C0–C4 每次都是新样本。

## 四、母题：还有哪些"没被发现的接口"

除你已知的三类（文生视频 / 文生图 / 首帧+文生视频），**盘点出这些成体系的能力**：

1. **首尾帧生视频**（10 个独立接口 + 23 个 i2v 带尾帧位）← 最值得先接
2. **参考生视频**（25 个，最多 7 张参考图；锁人物/道具身份）
3. **多模态生视频**（12 个，图 9 + 视频 3 + 音频 3 混合；`returnLastFrame` 可产尾帧）
4. **动作控制 / 动作迁移**（5 个，图 + 驱动视频）
5. **视频延长**（7 个，续原片最长 15 秒）
6. **视频编辑/重绘**（10 个，保留原运动换对象）
7. **视频转场**（3 个）
8. **数字人 / 口型同步**（5 个，音轨驱动）
9. **视频工具**：放大 5、补帧 1、提帧率 1、降噪 1、字幕擦除 2
10. **音频**：TTS 10、音乐 19、音色克隆 2、音频生成 1
11. **3D**：图生 3D 8、多视图 6、文生 3D 2
12. **理解类**：图生文 8、视频生文 4、文生文 4（可做"生成后自动判分"）

## 五、空档：RunningHub 现在**没有**的接口

| 缺什么 | 证据 | 影响 |
| --- | --- | --- |
| **抠图/蒙版/分割** | 420 个端点的参数里 `MASK` 类型为 0，端点名里无 inpaint/matte/segment/remove-bg | 抠图必须本地做（本仓库走 rembg，已跑通） |
| **尾帧单独喂** | 没有 `last-frame-to-video` 独立任务；尾帧只能进 `start-end-to-video` 或 i2v 的 `lastFrameUrl` | 想"只锁结尾"做不到 |
| **逐帧编辑（时间轴级）** | `video-edit` 是整条重绘，无区间/时间码参数 | 局部 3 秒改不了，只能整条重画 |
| **种子可复现** | 仅 `video-extend` 等少数带 `seed`；多数接口无 seed | 同 prompt 复现不可能 |

## 六、跟本账号的关系（2026-11-19 21:56 修订）

官方《Instructions for Use》把接口分成四类，**按 Key 类型授权，不按账号类型**：

| API 类型 | 能用什么 Key | 本账号（NORMAL，Consumer-Member） |
| --- | --- | --- |
| Model API（420 个标准接口） | **仅 Enterprise-Shared** | ✗ 1014 |
| LLM API | **仅 Enterprise-Shared** | ✗ |
| **AI App API**（现成应用，webappId） | Consumer-Member / Enterprise-Shared / Dedicated | ✓ 现役三条通道 |
| **Workflow API**（自己搭的 ComfyUI 工作流） | Consumer-Member / Enterprise-Shared / Dedicated | ✓ **已实测成功建任务** |

- 所以"必须建企业号"是**误解**：企业号解决的只是 **Model API + LLM API** 这两类；**出图出视频不需要企业号**。
- Workflow API 的契约（官方文档 `api-425761093`）：`POST /task/openapi/create`，body 里 `apiKey` + `workflowId` + 可选 `nodeInfoList`（逐节点改参：`nodeId`/`fieldName`/`fieldValue`）；还支持直接塞 `workflow`（整套工作流 JSON，**会覆盖 workflowId**）、`instanceType`（`default` 24G / `plus` 48G / `ultra` 84G）、`webhookUrl`。
- 这意味着 **C3 首尾帧不用等企业号**：在 RunningHub 上搭一条"首帧+尾帧→视频"的 ComfyUI 工作流（平台节点里 Vidu/Kling/Veo/Wan 都有），存成 `workflowId`，用同一个 Key 就能调。
- 现状仍是：手上三条现成 webapp 都没有尾帧位；差的不是权限，是**工作流本身没搭**。
