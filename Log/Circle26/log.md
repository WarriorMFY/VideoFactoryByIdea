## 2026-11-22 22:22 缝合器 `loop.py`

crossfade wrap：取前 K 帧 H 与后 K 帧 T，混合 B[i]=(1-a)T[i]+aH[i]，输出 = B + 中段 frames[K:N-K]。两处接缝都落在原片相邻帧上。

对比 K=6/8/12：

| K | 过渡 | 单元 | 接缝后 | ratio |
| --- | --- | --- | --- | --- |
| 6 | 0.25s | 4.92s | 0.9916 | 0.996 |
| 8 | 0.33s | 4.83s | 0.9995 | 1.004 |
| 12 | 0.50s | 4.67s | 0.9959 | 1.000 |

选 K=8。加 smoothstep 让混合在两端陡、中间快，缩短「半透明停留」。

十圈验证：1160 帧 / 48.3s，九个接缝 0.9931–0.9994，全片帧间中位 0.9969。**接缝不是异常点，比平均值还好。**

## 2026-11-22 22:24 两个必须记住的实测事实

1. **i2v 的第一帧不是底图**。末帧 vs 底图 NCC 0.6494–0.6775，末帧 vs 视频首帧 0.95–0.976。模型先重绘一版，再在里面运动。所以「忠于原画」这条路在 i2v 上不成立。

## 2026-11-22 22:37 零积分对照：纯剪辑版

用户指令：像「只有水在动」这种画面根本不需要生成模型——把水面区域横向缓慢平移、首尾无缝平铺，100% 保画风、零积分、绝对无缝。跑一版。

### 先按字面做（`water-flow.py`）

取水面 ROI，左右各取 200 列 crossfade 做成可横向平铺的纹理（周期 550px），每帧取一个 750px 窗口向外滚动，用「矩形羽化 × 亮度权重」贴回去——深墨（沙洲、山脚、树）不动，只有淡的水在流。

跑通了，接缝比值 1.000，288 帧 / 12s。

**但它把水面重排了。** 可平铺纹理必须先裁掉两端再交叉融合，纹理宽必然小于 ROI 宽（550 < 750），平铺后画面里是「同一小段水纹重复三次」。实测：

| 帧 | vs 原画 NCC |
| --- | --- |
| f0 | 0.9318 |
| f72 | 0.6566 |
| f144 | 0.5897 |
| f287 | 0.8780 |

一圈之内，水面从「像原画」漂到「不像」再漂回来。它不是「原画在动」，是「原画的水被换成了一段重复纹理」。

### 改做位移场（`water-wave.py`）

像素一个都不生成，只改采样位置：

```
out(x,y) = src( x + dx, y + dy )
dx = A(y) · sin(2π( x/λx − t/T + y/λy ))
dy = r · A(y) · cos(2π( x/λx − t/T + y/λy ))
```

像素值全来自原画，画风零改动；位移场是 t 的周期函数，t=T 时相位与 t=0 完全相同，所以严格无缝且不需要过渡帧；幅度按 y 递增（远静近动），并在深墨与岸线处衰减到 0，所以沙洲山脚不被拖走。

中间踩了两个坑：

1. **第一版 ROI 取小了**（x 430–1180），只有画面中段那一小块水在动，其余水面全静着。mask 图一眼看出来。扩到 x 0–1700、y 425–790，靠亮度权重自动避开岸树与山脚。
2. **横向位移看不出在动**。amp=11、纯横向时帧间 Δ 只有 0.051——因为古画水纹是横向拉长的短线，左右挪十来像素时线条端点几乎不动。把纵向分量提到与横向相同（`--dy-ratio 1.0`）、amp 加到 16，水纹才呈波浪状起伏，帧间 Δ 到 0.574。

也试过「整体往复漂移」把接缝藏在左岸树丛（`--sway`），结果 `np.roll` 作用在整幅图上，山和树一起被搬走，与原画 NCC 掉到 0.25。放弃，参数保留但默认 0。

### 三版对照

| --- | --- | --- | --- | --- | --- |
| i2v L2 | 18.53 | 124 / 5.17s | 0.666 | 0.9504 → 缝合后 0.9995 | 0.549 |
| flow 平移 | 0 | 288 / 12s | 0.974 均值，中段 0.59 | 0.9943 | 0.602 |
| wave 位移场 | 0 | 144 / 6s | 0.891 | 0.9974（比值 1.000） | 0.594 |

### 一条数学约束（本轮最该记的）

**单向平移、无重复、严格无缝，三者互斥。** 无缝要求偏移按周期回环；无重复要求周期 ≥ 画面宽；两条同时成立时纹理就是画面本身，而画面首尾本不相接。剩下的只有两条路：过渡段（水纹会淡一下）或重复（画面里出现第二份水纹）。

所以「像水在流」和「一点不变形」只能选一个。要两头都占，必须让动态主体周期性离场，把接缝落在空画面上——那正是待验的第一条（鸟飞出去）。

## 2026-11-22 22:58 记录：剪辑路线的性价比边界

用户判断：这也算一种低成本方式，在某些场景比模型生成更具性价比。判据记下来，供后续选路。

### 先问一句，决定走哪条

**这一段要动的，是不是「原来的像素换了个位置」？**

是 → 剪辑。不是（有形状变化、有新内容进场、有遮挡交互）→ 模型。

### 剪辑占优的四类场景

| 场景特征 | 例子 | 为什么模型反而输 |
| --- | --- | --- |
| 只有位移，无拓扑变化 | 水纹、云、雾、烟、光斑、雨、雪、落叶 | 模型必然重绘，画风与细节跟着漂 |
| 基座信息量大且不可重绘 | 古画、带文字的界面、有设计稿的场景 | i2v 第一帧就已重绘（NCC 0.65），飞白与绢纹直接丢 |
| 要求帧级严格闭合 | 桌面壁纸、展厅长播、投屏 | 剪辑天然闭合（接缝比值 1.000）；模型要事后缝合，还有「淡一下」 |
| 长时长 / 高分辨率 | 60s 以上、1080p 以上 | 模型按秒按像素计费，输出上限 1056x608；剪辑无边际成本 |

### 模型不可替代的四类

| 场景特征 | 例子 |
| --- | --- |
| 有拓扑变化 | 由线化人、花开、显形、碎裂重组 |
| 需要生成原画里没有的东西 | 主体入场、镜头运动、光照改变 |
| 主体与遮挡物要有正确交互 | 穿过树丛、被前景遮住、绕行 |
| 非刚性有机形变 | 衣袂、毛发、水花溅起 |

### 剪辑独有的两条性质

1. **确定性**：同一输入永远同一输出，可复现、可调参、可批量重跑。模型是抽样——本轮两次证实同参数不同价（21.42 / 17.51 / 17.68），结果也不同。
2. **不降级**：本轮剪辑输出 1800x1012 原生，i2v 只给 1056x608。对古画这种靠绢纹与飞白立命的素材，分辨率本身就是画风。

### 一条成本对照

i2v 一条 5s 实扣 18.53，要做到 60s 还得循环缝合，且画风已经漂过一轮；剪辑同样 60s 零积分、原生分辨率、画风零改动。

**在这类「只有位移」的镜头上，模型是负资产。**

## 2026-11-22 23:10 第二条路线：图生图出尾帧 + 首尾帧生视频 + 乒乓环

用户指令：基于模型的循环视频，先基于首部关键帧走图生图出尾部关键帧，再走首尾帧生视频出循环视频；给了张发光白鹿的青绿山水截图，问尾帧该是啥、动态提示词是啥。随后一句「跑」。

### 判断：这张图只有「光」能承受无限循环

鹿是发光雕像，身体、四足、鹿角一动就回不来；石阶、山壁、青绿山、枯枝同理。剩光、雾、光尘——无方向的连续场，这才撑得起环。

尾帧因此不能等于首帧（两端相同，模型最省力的解是「什么都不做」），要出成半个周期之后的状态：光衰、雾散、尘升。往暗走而不是往亮走，因为首帧左下金光已最盛，再亮就过曝。

### 尾帧：模型把鹿重画了

`flux3-edit`（webapp `2114585366186516481`）3:2 出两张，task `2124522802542501890`，实扣 **22.10**。

| | 与原图 NCC | 鹿剪影 IoU | 鹿白面积 | 质心位移 |
| --- | --- | --- | --- | --- |
| out_1 | 0.9179 | 0.598 | 21176 → 12719 | +37, −18 |
| out_2 | 0.9607 | 0.631 | 21176 → 13128 | +31, −15 |

（IoU 用归一化亮度阈值算，排除「变暗导致高亮像素变少」的干扰。）

提示词里明写了「不改变姿态、角度、四足落点、长鬃走向」，模型照样把鹿缩小了三分之一并右移。图生图必然重绘整幅，这是路子本身的性质，不是提示词没写好。

### 改法：模型只给「光怎么变」，结构仍取首帧

```
gain = GaussianBlur((B+8)/(A+8), σ=40)     # 只留光照的缓慢变化
gain = clip(gain, 0.55, 1.25)
core = clip((A_gray-165)/75, 0, 1)          # 鹿芯：越白越保护
core = GaussianBlur(core, σ=3)
g    = gain·(1−core) + 1.0·core
B'   = A × g
```

σ=40 是关键：小核（σ=25）也保留了一部分模型改过的轮廓，大核只留亮度。护住鹿芯是为了不让「光衰」把鹿的白光一并压成灰。

结果：`ncc(A,B') = 0.9886`，全图 −11.4%，鹿芯 209.6→195.2，左金光区 177.8→155.4，鹿轮廓像素级不动。

### 乒乓环 `pingpong.py`

单元 = `f0..fN-1` + `fN-2..f1`。末帧 f1 与下一单元首帧 f0 是原片相邻帧，接缝跳变严格 0，**不需要 crossfade，也不要求两端长得一样**。

- 单元 96 帧 / 6.00s；折返 NCC **1.0000 / 0.9988**，帧间中位 0.9999
- 十圈 960 帧 / 60s / 4.8MB

这才是首尾帧路线的真价值：**折返点正好落在你设计的两张锚上**。A 亮、B 暗，一圈就是「光盛→光衰→光盛」。

代价：有方向的运动会被倒放反转（落花变上升、外扩涟漪变收缩），只能用于无方向周期运动。

### 这一版动得太少

亮度曲线（每 0.25s 采样）：135.0 133.9 125.6 120.4 119.9 119.7 120.9 121.0 121.4 121.7 122.5 122.4。

1 秒内掉到谷底，之后缓慢回升 2%。首末差 −12.6，方向对，但**帧间 Δ 中位只有 0.296**，3×3 分区运动量 10–15（0–255），等于「一张静图在缓慢明暗」。

问题不在通道，在**两端设计得太近**：A→B' 只差 11% 亮度，模型没有可插值的余量，于是它把变化全放在前 1 秒做完。要更有活气，得把摆动加大，或者让 B 里多一样真会变的东西（雾的形态、光尘位移），而不是只改亮度。
