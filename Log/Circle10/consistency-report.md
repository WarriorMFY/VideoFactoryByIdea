## 一、结论先说

| 判断 | 依据 |
| --- | --- |
| **身份：两次出的接近同一人，但不是同一张脸** | 眼位对齐后跨片 NCC **0.758**（正脸段），片内 0.935–0.994；参照「同卡两张静态图」0.644（Circle8 判为两张不同的脸） |
| **动作：两次一条守规矩、一条不守** | a 从侧脸闭眼起手，1.5–3.2s 转正并把脸推近 33%；b 全程正脸、零推拉、脸位漂移 <1% |

## 三、片→片身份一致性（M8 替代 M9）

环境无 insightface／onnxruntime，ArcFace 不可用。改用**眼位对齐 + NCC**：Haar 眼级联取双眼，按瞳孔距归一到 100px、按眼线旋转归零，再取固定窗口（300×380）算相关。

| 样本对 | NCC | 说明 |
| --- | --- | --- |
| 片内 a3↔a5 / a4↔a5 | 0.935 / 0.979 | 同一张脸、不同时刻的上限 |
| 片内 b3↔b5 / b4↔b5 | **0.994 / 0.993** | 同上，b 机位完全静止 |
| **跨片 a3↔b3 / a4↔b4 / a5↔b5** | **0.760 / 0.775 / 0.758** | 本轮要回答的数 |
| 跨片（含转头段 0–2s） | 0.464–0.750，mean 0.684 | a 侧转帧与 b 正脸不可比，只作参考 |
| 参照：still-880 ↔ still-1086 | 0.644 | Circle8 判为**两张不同的脸**（跨尺寸） |
| 参照：still-1086 ↔ b3 | 0.805 | b 与「1086 那张脸」高度接近 |
| 参照：still-880 ↔ a3 | 0.525 | a 离两张静态图都更远 |

**读法**：跨片 0.758 高于「两张不同脸」的 0.644，低于同脸同片的 0.99。也就是说，**两次视频落在「同一人但重新采样」这一档**，比静态图那次跨尺寸重掷更接近，但远远达不到片内稳定。

一个额外的信号：b 与 1086 静态图的 0.805 明显高于 a（0.525）——两次不是均匀地「都在中间」，而是 b 贴住了其中一张既有静态图，a 两张都不贴。这与 Circle8「同一张卡下并存两张脸」的结论吻合：**卡的输出空间本来就是多峰的，视频只是各自落在了不同峰上**。

目视复核（眼位对齐后同尺度对比）：正脸段（3–5s）判为同一人；差异集中在**唇厚（a 更薄、b 更饱满）、下颌宽度（b 更宽）、眉的浓密（b 更粗）**。

| 瞳孔距极差 | 0.138（0.411–0.549） | **0.012** |

b 是「几乎不动」的那条：瞳孔距极差 0.012 相当于全程脸大小变化 1.2%，等于码流抖动级别。a 的 33% 推近不是抖动，是**真的在推镜头**——这直接违反了视频卡「零推拉摇移」。

## 五、构图合规（要求 vs 实测）

| 要求（卡内原文） | v1-a | v1-b |
| --- | --- | --- |
| 3:4 竖幅 | 640×832（0.769）偏 2.6% | 同 |
| 脸宽占画面宽 70% | ≈100%（脸左右出血） | **88%**（全脸级联框/画幅宽） |
| 全头完整入画 | ✗ 发顶被切 | ✗ 发顶被切 |
| 发顶距顶 8% | **0** | **0** |
| 下缘落在锁骨上方 | 下巴+颈根（略高） | 颈+裸肩（略低） |
| 人脸水平居中 | 近似 | 近似 |

**「70%」「8%」两个数字一个都没生效**，而「全头完整入画」这条纯语义要求同样没生效——两次都给了同一个默认：**脸占满画幅的极特写**。这不是数字参数失效，是卡内语义被更高优先级的句子带走了：肖像卡写「画面裁到只剩脸」，视频卡又写了「冲突时以肖像卡为主」，模型于是照脸特写办。

| 要求 | v1-a | v1-b |

| 全程正视镜头 | ✗ 0–1.5s 为四分之三侧脸 | ✓ 全程正脸 |
| 不转头 | ✗ 有一个缓慢回正 | ✓（仅 ±1.2° 倾角抖动） |
| 零推拉摇移 | ✗ 推近 33% | ✓ |
| 一镜到底、无剪辑 | ✓ | ✓ |
| 只在 2–3s 眨眼一次 | ✗ 0s 双眼闭合（闭眼而非眨眼） | 未见眨眼（0.35s 采样 15 帧全睁；无法排除 0.2s 级瞬闭） |
| 不开口 | ✓ | ✓ |

同一个 prompt，一条把「回正」演成了开场表演，一条老老实实静止。**这与 Circle5/6 的结论同源：节奏类、状态类要求能守，事件类、动作类要求会各自发挥。**

## 八、与 Circle8（文生图）的对照

| 项 | Circle8 静态图 | Circle10 视频 |
| --- | --- | --- |
| 一致性口径 | 同卡异图 0.777（880 组）/ 0.908（1086 组） | 跨片 0.758（眼位对齐 NCC） |
| 跨次差异来源 | 尺寸二分 → 两张脸 | 无尺寸变量，仍出两张脸 |
| 颜色 | 未量化 | 跨片差 1–3 点，色相偏 14° |
| 卡内数值 | 脸宽 87%、三庭等比等多项未对齐 | 取景 70%／8% 全部未生效 |

**关键差别**：静态图那次还能把「两张脸」归因到服务端两套 1k 像素预算（880 / 1086）；这次视频没有尺寸变量，同样出了两张脸——**说明多峰不是画幅造成的，是模型在「这张卡描述的这个人」这个语义域里本来就有多个吸引子**。这一条把 Circle8 的结论从「尺寸导致」修正为「尺寸只是选中了不同的峰」。

## 九、这轮最值得记的三条

1. **视频的取景数字比图片更不管用**：图里 87% 还能凑合，视频里 70%/8% 直接归零，模型一律给脸特写。取景只能靠语义写（「头肩」「全头在画内」），不能靠百分比。
2. **同 prompt 两次，一条守规矩一条不守**：这不是随机抖动，是两条不同的「导演选择」——a 自作主张加了一个转正 + 推近的开场。要压住它，卡里得写「第一帧就是最终构图，前 2 秒不得改变脸在画面中的大小与朝向」。
3. **裸肩是个副作用**：肖像卡「脸以外不写」＋视频卡「下缘锁骨上方」＝画面出现无衣的颈肩，观感像悬空的头。要么在视频卡里补一句衣料（中性灰圆领），要么把下缘收回到下巴。
