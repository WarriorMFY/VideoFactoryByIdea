# Log · 历史留痕

## 一、定位

Log 是**原料层**：仓库里的一切都从这里的实验诞生，再按事实分头流向 `Doc/`、`Tool/`、`Skill/`、`RAG/`。

- **只记当时**：做了啥、产出了啥、结论是什么。已写下的不再回改——上层路径变了也不回头修。
- **零出链**：不 import 任何代码，不调用 `Skill/`、`Tool/` 的脚本。
- 两条允许：脚本可以读 `RAG/` 的数据文件（原料在库）；文字里出现路径（如「跑了 `python Tool/ffmpeg.py -version`」）是事实记录。

## 二、目录

每轮一个 `Circle<id>/`，由用户说「新建循环」创建、「结束循环」收尾，AI 不自建不自结。

最小要求：

| 文件 | 内容 |
| --- | --- |
| `Circle.md` | 开始时间、结束时间、中间过程；结轮后只保留摘要（一句话做了什么／结论／待优化） |
| `log.md` | 详细日志；结轮时把过程从 `Circle.md` 下移到这里 |

其余（`prompt.txt`、产物目录、`ledger.json`、当轮脚本）按需建，不强制。

## 三、纪律

1. 结轮自动提交本地 git（见 `AGENTS.md`）；平时不提交。
2. Log 下的 `.py` 是当时的现场器材：可能引用已变更或已删除的路径，**不保证可运行、不随上层修复**。要复现某个结论，用 `Skill/` 的现役脚本，不要修这里的旧脚本。
3. `Log/` 下的媒体不入库（见根 `.gitignore`）；`RAG/` 的媒体入库。
