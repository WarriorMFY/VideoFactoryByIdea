## 工具清单

| 工具 | 用途 | 状态 |
|---|---|---|
| [`bgm_fit.mjs`](bgm_fit.mjs) | **卡点对齐器**：给定候选音乐 + 成片命中点时间表，在 ±search 相位窗内找最优 offset，输出每个 hit 的对齐误差（ms/帧）与 PASS/FAIL 判定；`--mix` 直接产出对齐混流视频 | ✅ 已验证（自测：合成曲 offset 0 / 误差 ≤5ms；判别力：旧曲对新合集 4 hit 中 3 FAIL）。**2026-11-08 修两处**：① 曲长不足时不再崩溃，改输出诊断并 exit 2；② 搜索窗内无瞬态的点标 `NO-ONSET`，不再给假 onset |
| [`bgm_scan.mjs`](bgm_scan.mjs) | **批量选型扫描**：目录内全部音频逐首跑 bgm_fit，按误差均值排序，标出「无瞬态 / 曲长不足」，可写 CSV；有全 PASS 候选时 exit 0 | ✅ 17 首实测（loop43：最优 1 首均值 166ms、6 首不可评估） |
| `rebuild_audio.mjs` | 逐镜变速重建原声（atempo 保音高），mux 回 recam 成片 | 暂在 `Prototype/loop42_speed_grammar/`，按 §1.5 待判定沉淀 |

## bgm_fit 用法

```bash
# 度量：这首曲子卡不卡点
node Tool/audio/bgm_fit.mjs --music <audio> --hits 0.95,5.43,10.12,13.07 --dur 18.98

# 对齐并混流（视频流 copy，音乐按最优 offset 移位）
node Tool/audio/bgm_fit.mjs --music <audio> --hits ... --dur ... --mix <video.mp4> <out.mp4>
```

参数：`--search 2.0`（相位搜索半窗，秒）· `--tol 0.05`（容差，默认 3 帧@60fps）· `--fps 60`。

## BGM 选型判据（四条，按序卡）

1. **卡点**：`bgm_fit` 全部 hit PASS。误差为负 = 音乐先响（可接受到 −1 帧内，先响后打是常见打法）；超出 ±tol 判 FAIL。
2. **瞬态存在**：曲子在 hit ±0.25s 内必须有可闻 onset（能量差分峰）。纯弦乐/氛围垫没有瞬态，天然 FAIL——这不是曲子差，是不适合卡点混剪。
3. **时长与结构**：曲子可用段 ≥ 成片时长 −1s；前奏过长会在 ±2s 搜索窗内找不到可用相位（表现为 FAIL 或 offset 顶到搜索边界），此类需人工截取。
4. **版权**（发布闸门，人工定）：内部评估任意曲；对外发布走平台授权曲库（B站创作中心音乐库 / 抖音商用音乐）。不做变速、加噪声等规避检测的手段。

## 已知边界

- 只度量"对齐质量"，不判曲风/情绪——那是人评；
- onset 用 5ms 能量差分，对无瞬态曲失真（判据 2 会先拦住这类曲）；
- 不自动检测 BPM；段落结构（前奏/鼓组密度/过门）由人听。
- **变速成片的命中点不是节拍网格**（2026-11-08 实测结论）：各单位内部变速比不同，输出时间轴上的命中点间距为 5.48/5.03/3.10/3.95/5.37/1.25s，互不成整数比；穷举 100–180 BPM 后无任何拍长能让 6 个间距同时落格（最好 BPM 144 均值残差仍 0.08 拍 ≈ 33ms，个别点 59ms）。**推论：对变速成片，"7 点全 PASS（±50ms）"在原理上几乎不可达**——17 首实测最优者也只有 1/7 PASS（均值 166ms）。可行路线：① BGM 只承担氛围与段落结构，逐点卡点交给**音效补点**（与"处决片力度七成在音效"一致）；② 先选曲再按音乐重音重排单位长度（反向作业）；③ 放宽 tol 到 ±0.15s 并用瞬态密度兜底。选哪条由人定。
- **曲长 ≥ 成片时长 −1s 是硬门槛**：否则尾部命中点落在曲外，bgm_fit 现在会直接判"无法评估"而不是给一个勉强的高误差读数。
- 素材来源须记授权：Incompetech（Kevin MacLeod）为 CC BY 4.0，可商用但**必须署名**，且多数曲目在 YouTube Content ID 有登记（发布易被 claim，需申诉）；对外发布仍优先平台授权曲库。
