## 素材与切点（probe/ 实测，经 4 轮抽帧修正）

- 源片：`Material/library/video/e7e889f4_yzl-exec-60.mp4`（1080p60，173.04s），u01 = 源 0.08s 起 3.65s（loop38 catalog：标准级「夜祭坛·镰刃连杀蓝发大汉」）
- u01 内部 **3 个原生切点**（段内时间）：**1.70 / 2.52 / ~2.80**（第三个在 2.80–2.85 之间）
- 由此 u01 = 四层：**起手（0–1.70，室内红调中景）→ 蓄势（1.70–2.52，蓝灰近景·咒物锁头）→ 命中（2.52–2.80，中景·红光刃环绕爆发）→ 余韵（2.80–3.65，室外全景·收招）**
- 教训：0.05s 细网格在 300px 缩图上误判两次（把近景内挥刃判成"切中景"、把 2.75 判成全景起点）；切点判定必须 ≥560px 单帧取证

## 语法草表（V2 终版配方，待人工否）

| 镜 | 段内 t | 景别（cam） | 速度 | 拖影 | 表达意图 |
|---|---|---|---|---|---|
| 1 | 0.00–1.70 | full（原机位中景） | 1.0x | — | 起手层：原速铺陈，交代空间与双方 |
| 2 | 1.70–2.52 | full（原片已切近景） | 0.65x | — | 蓄势层：减速预告「重击将至」 |
| 3 | 2.52–2.76 | crop 1280x720（推近一级） | 0.3x | 3 帧 | 命中层：升格 + 拖影 = 重量感 |
| 4 | 2.76–3.65 | full（原片切回全景） | 1.8x | — | 余韵层：切全景同时骤然加速，压缩站桩 |

时长：原 3.65s → v2 约 4.20s（升格膨胀被余韵加速抵消）；v1 对照 7.30s。

候选语法句（本轮验证对象，人评）：

1. **景别越近，速度越极端**——全景/中景层 1.0–1.8x 中性偏快，命中特写层 0.3x 极端慢放；速度差本身制造层级感。
2. **慢放只给命中**——整段均匀慢放（v1）把 3.65s 拖成 7.30s，重量感被摊薄，没有「重击」存在；慢放必须稀缺。
3. **慢→快的骤变借切点发生**——镜 3 特写 0.3x 结束在原生切点前，镜 4 借同一切点跳全景并提速 1.8x：景别与速度同时反向跳变，鞭打感最烈。
4. **余韵层加速是清理**——收招站桩对表达无贡献，1.8x 压掉，把观众注意力还给下一刀。
5. **变速窗口必须避开原生切点 ±2 帧**——镜 3 首版收到 2.82，把切点后 3 帧全景升格进特写框，出现「特写框里的全景」跳变；收到 2.76 修复。速度再慢，一帧错位都会被放大 3–4 倍。

## 三组合集（人工反馈「基本满足」后追加，2026-11-08 13:42）

## BGM 配乐（人工反馈「在 B 基础上配 BGM」后追加，2026-11-08 13:57）

`setB_重击_bgm.mp4` = 修正后的 B 组合集 + 程序化节拍 BGM（零版权、可复现）：

- **生成**：`python make_bgm.py bgm.json bgm_B.wav`（标准库 wave，纯 Python 合成）——120 BPM 底鼓每拍 + 军鼓每 2 拍 + hi-hat 每 1/2 拍 + 41Hz 低频 drone；三个命中冲击（38Hz 次低频 + 噪声爆）精确落在实测命中层起点 0.85 / 5.395 / 10.606s
- **听觉语法（候选第七句）：慢放窗抽掉节拍，只留低频**——三个命中层窗口（0.85–1.75 / 5.395–6.195 / 10.606–12.339s）内 kick/snare/hat 全部静默、drone 反升 1.6 倍：画面减速时听觉同步变空，重击落点形成「满→空→冲击」循环。波形核对 `probe/wave_bgm.png`
- **音画对位核对**：重击 +0.1s 三帧抽验，均落在命中爆发画面（`probe/sync_strip.png`、`sync_10.71.png`）
- **混流**：`ffmpeg -i setB_重击.mp4 -i bgm_B.wav -c:v copy -c:a aac -af loudnorm=I=-14:TP=-1.5:LRA=11 -shortest`，实测 mean -15.7 dB / max -1.1 dB
- **时值来源**：`bgm.json` 记录全部时间轴参数（dur / hits / quietWindows / fills 段边界过门）——先渲染后实测时长，再写进配置，BGM 生成不依赖估计值

## 原声回填（人工反馈「先补原声」后追加，2026-11-08 14:33）

**背景判定**：配乐版被否后实测发现，真病根是 recam 全链 `-an` 把源片原声丢了——u01 命中窗比起手窗 **RMS +6.1dB / Peak +7.6dB**（`probe/src_wave_u01.png`、`probe/src_spec_u01.png`），刀风/命中/低频爆的声源本来就在源片里；且合成 BGM 的"慢放抽鼓点"是假的（drone 仍 -10.5dB，比命中窗还响）。**处决片力度七成在音效**（候选第八句）。

- **工具**：`rebuild_audio.mjs`——读 recam 配方，按每镜 speed 用 atempo 链逐镜变速重建音轨（保音高，atempo 单级限 [0.5,100]，0.3x 需级联 0.5×0.6），视频流 copy 不重编
- **三个坑**：① 同一输入流被 N 路 atrim 消费必须先 `asplit`（否则只出末段）；② output 侧 `-ss` 令音频时间戳错位（音频 seek 本身精确，单次 input seek 即可）；③ output 侧 `-t` 会把变速拉长后的音频截回源长（`-t` 必须在 `-i` 前）
- **产物**：`setA/setB/setC_原声.mp4`（11.32 / 13.84 / 9.24s），三段音画时长差均 <4ms；命中对位验证：命中窗峰值 -5.4/-1.1/-2.3dB vs 非命中窗 -6.5/-9.1/-4.9dB
- **站点**：原声版升为主推，配乐版降级为对照卡（「原声优先」结论的直接证据）
- **遗留**：① 0.3x atempo 保音高但拉长瞬态（慢放"糊"是物理事实），要重击感可另加降调（asetrate）；② `rebuild_audio.mjs` 为执行体雏形，验证后判定是否合入 recam 正式音频通道
