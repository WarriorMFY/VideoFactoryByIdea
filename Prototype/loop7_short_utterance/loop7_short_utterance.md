## 说明（原 `README.md` 正文）

### 小循环 7 · 真实影视"短句漏识"：一条被证伪的假设 + 一条落地的改进

> 素材：Tears of Steel（© Blender Foundation，CC-BY 3.0）90s 对白密集片段，真值取官方英文字幕。
> 结论一句话：**想把漏掉的短句"救"回来 —— 没成功，而且能证明救不回来是模型上限；但顺手把音频预处理链调准了（WER 31.6% → 28.4%）。**

#### 1. 这一轮想干什么

小循环 4 的实测数据说：真实影视素材上 WER 30.5%、语音覆盖 59.9%，**漏掉的几乎全是 1–3 词短句**
（`Abort!` / `Cut!` / `Nooooo!` / `I know.`，短句覆盖率只有 24%）。

我的假设是：这些句子**有声音但没被识别**，如果把那些片段单独切出来、滤波放大后再识别一遍（"救援"），
应该能救回一批。这是本轮要验证的东西。

#### 2. 做了什么

| 组件 | 作用 |
| --- | --- |
| `Tool/subtitle/asr_rescue.mjs` | 新增：用 20ms 帧能量找"有声区间"→ 减掉基线已覆盖的部分 → 逐窗滤波放大重识别 → 按置信度/时间重叠过滤后合并 |
| `Tool/lib/vosk.mjs` | 重构：把 Vosk 识别内核抽成库，模型只加载一次、识别器每段新建（**踩坑见下**） |
| `Tool/lib/srt.mjs` | 重构：SRT 写出统一成一份实现（供小循环 8 的"回写"复用） |
| `Tool/setup/fetch_tos_movie.mjs` | 补齐：顺带下官方英/中文字幕（真值来源），且字幕缺失时不会因为"电影已下完"而跳过 |
| `Tool/acceptance/run_rescue_acceptance.mjs` | 验收：4 条判据（改进落地 / 跨素材不倒退 / 证伪证据充分 / 不伤中长句） |
| `History/probe/loop07_*.mjs` | 三支探针：预处理链穷举、干净 TTS vs 混音、跨素材复核 |

#### 3. 结果（都能复现）

| 项目 | 不处理 | 最优链（新默认推荐） | 最优链 + 短句救援 |
| --- | --- | --- | --- |
| WER | 31.6% | **28.4%** | 28.4% |
| 识别词数 | 82 | 79 | 82 |
| 语音覆盖 | 53.8% | 50.3% | 51.9% |
| 短句覆盖（1–3 词） | 13.8% | 11.1% | 14.1%（+3.0pp，**目标 +10pp 未达成**） |
| 中句 / 长句覆盖 | 66.5% / 84.5% | 62.2% / 83.5% | 63.5% / 83.5% |

最优链：`--af "afftdn=nf=-25,highpass=f=200,lowpass=f=4000"`。
注意它是"**更少乱猜**"而不是"听得更多"：WER 变好、词数和短句覆盖略降（降噪把被音乐压住的小声对白一起压掉了）。

#### 4. 为什么救不回来（本轮最值钱的部分）

把基线漏掉的 10 条真值短句单独拿出来，分别喂"干净 TTS"和"原片对应时间点的混音"：

| 真值 | 干净 TTS 识别 | 原片混音识别 |
| --- | --- | --- |
| Speed it up, Thom! | speed it up tom | （空） |
| Vivacissimo! | there was this ammo | （空） |
| Abort! | abort | （空） |
| Cut! | cut | （空） |
| Whoaaa! ×2 | woah | （空） |
| Nooooo! | no | the the |
| I know. ×2 | i know | you / no |
| I'm- | i'm | （空） |

- **干净语音 8/10 "听得出来"，原片混音 0/10** → 不是词表里没这些词。
- 再把 7 条预处理链（带通/降噪/动态归一/语音归一/增益/组合）逐一试在这些片段上：**最佳一条也是 0 命中**。
- 把窗口放大到 6s / 10s 给上下文：仍然 0 命中，`I know.` 会被整段跳过。
- 结论：**这是 Vosk 小模型的声学能力上限，不是"喂法"问题。** 要解决只能换 Whisper 级模型，
  而本机 HuggingFace / ModelScope 全域不可达（`vosk-model-en-us-0.22` 1.9GB 用 alphacephei 40s 只下了 2MB）。

#### 5. 踩到的坑（已修，写进代码注释）

1. **Vosk 的 recognizer 是有状态的**：复用同一个 recognizer 识别第二段音频，时间戳会接着上一段累加
   —— 90s 素材的救援窗里出现了 `105s`、`112s` 的词。模型可复用，recognizer 必须每段新建。
2. 短窗（1–2s）解码时端点检测常常不命中（`acceptHits=0`），`final_result` 几乎总是空 —— 这本身就是"救援"思路失效的原因之一。
3. 同一条处理链，**同进程连续识别**比**新进程单段识别**偶尔差 1 个词；对外报数统一用 `asr_vosk.mjs`（新进程单段）。

#### 6. 怎么复现

```powershell
# 依赖 + 素材（TOS 电影 355MB + 官方字幕 + 90s 片段，幂等）
.\Prototype\loop7_short_utterance\reproduce.ps1
```

脚本会依次跑：基线（不处理）、基线（最优链）、短句救援、三支探针、分桶验收，最后打印 PASS/FAIL。
首次跑要下 355MB 电影（dotsrc 12 线程约 0.4 分钟）。

#### 7. 结论与下一步

- ✅ 落地：`asr --af "afftdn=nf=-25,highpass=f=200,lowpass=f=4000"` 作为**真实影视**的推荐预处理链（WER 31.6% → 28.4%，Sintel 上置信度也不倒退）。
- ❌ 证伪：靠"切窗重识别"救短句，在当前模型上无效（+3pp，救回 0 条真值行）。
- 🔁 保留：`asr_rescue.mjs` 的"找未被识别覆盖的有声区间"能力，可以当**漏译检查器**用，换模型后直接复用。
- ➡️ 下一步（按收益排序）：
  1. **换 ASR 模型**（唯一能真正解决漏句的路），需要人提供：模型文件 / 可用下载通道 / 一个 ASR HTTP 接口；
  2. 长视频（49min）压测 + 离线翻译后端（工程风险，不改变能力）；
  3. 术语一致性检查（等小循环 8 的校对表落地后，天然是表上的一个 flag）。
