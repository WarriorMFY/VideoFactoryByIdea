## 说明（原 `README.md` 正文）

### loop33 · 镜头语言重加工实验（数字重摄影）

**实验问题**：能否在不改变人物与动作内容的前提下，对一段动作镜头做「镜头语言的重新加工」？

**结论：可以。** 用「数字重摄影」——在单机位素材上做裁切重构景别、运镜轨迹、变速与拖影，动作本体一帧不改。成片 `out_rephoto_test.mp4`（18.0s / 1080p / 无声 / 15.4MB）。

#### 素材与结构

- 素材：紫冥剑 299.0−302.2s（空中翻腾 → 落地大横扫 → 收势），从 1080p 源双 seek 精确切出 `build/clip_src.mp4`（96 帧，PTS 归零）
- 成片 6 段：字卡 → ①原镜头 → ②推轨近景 → ③多机位伪造 → ④速度斜坡 → 尾卡

#### 四种镜头语言

| 版本 | 手法 | 实现 |
|---|---|---|
| ① 原镜头 | 对照组 | 游戏内固定机位 |
| ② 推轨近景 | 2× 超采 → zoompan 推近 1.0→1.4 + 跟随摇移 + vignette + 2.35:1 遮幅 | zoompan x/y 线性表达式 |
| ③ 多机位伪造 | 单素材切 5 段不同景别硬切（全景/中景右上/低机位/剑光特写/收势缓摇），段间 vignette+遮幅统一质感 | split+trim+各段 crop+concat |
| ④ 速度斜坡 | 剑光横扫段 0.35× + tmix 3 帧拖影 + colortemperature 9500 + 降饱和 | trim+setpts=2.857*PTS |

#### 关键经验（实踩）

1. **中文标注必须走 libass**（`ass=` 滤镜 + UTF-8 ASS 文件）：drawtext 的中文在 Windows 命令行/node execSync 下必坏（方框或黑屏），fontconfig 缺失加剧。loop28 已知，本次再次确认。
2. **`ass=` 用相对路径 + cwd 切到 build 目录**——绝对路径的冒号转义地狱直接绕开。
3. **trim 分段必须先切干净中间文件**（PTS 归零），不要在双 seek 输出流上 trim（时间基准不可靠）。
4. **execSync 传参**：cmd.exe 语义下只给含空格的参数加引号，`-f lavfi` 这类短 flag 不能带引号；`-f lavfi` 必须 `-f`/`lavfi` 两个 token。
5. **concat demuxer 的 file 列表用正斜杠**；lavfi color 段与素材段用 concat 滤镜拼时时间轴会错位 → 分段贴字幕再 concat demuxer 才稳。
6. **V2 多机位段的 crop 窗口必须按角色真实轨迹标定**：角色 0.45−0.85s 从右上高速移到左下，固定轨迹跟拍必然出画；窄时段 + 固定窗口才是对的。

#### 边界（诚实声明）

- 2.5D 限制：无法改变透视与遮挡关系（单视角素材），「新机位」是伪造的构图，不是真实视差
- zoompan 放大有轻微画质损失（2× 超采缓解）
- 无法做真实景深；浅景深只能伪造（未做）
- 若要真·AI 重拍（新机位视差），需视频生成模型，但那会改动动作本体——与实验前提冲突
