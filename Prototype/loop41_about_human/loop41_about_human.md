## 第二段（19:58–22:05）：LLM 上下文注入机制

> 起因：人提出「咱俩要深度合作，我必须知道你都听谁说了什么话」。此段**不改任何仓库文件**，只做实测与推演，结论决定以后规则该写在哪里。

### 一、先分清三层，否则后面全是错的

| 层 | 是什么 | 它决定什么 |
|---|---|---|
| **宿主** | WorkBuddy 桌面客户端（`E:/SoftWare/WorkBuddy`，Electron 应用；数据目录 `C:/Users/59784/.workbuddy`） | 我这一轮**能看到什么**：系统提示、工具清单、项目 `AGENTS.md`、hooks、文件权限 |
| **模型** | 远端 API | 我怎么处理看到的东西 |
| **我** | 模型 + 工具循环 | 只能读文件，**不能给自己注入任何东西** |

「注入」这个动作只有宿主能做。说「宿主不读 `USER.md`」，准确含义是：客户端启动会话时不把该文件放进我的输入。

### 二、六层输入，按权威从高到低

| # | 来源 | 谁能改 | 大致内容 | 效力 |
|---|---|---|---|---|
| 1 | 宿主内置 | 谁都改不了 | 安全边界、工具规范、输出格式、身份设定 | 最高，不可违、不可覆盖 |
| 2 | 人当轮说的话 | 人，随时 | 打的字、附件、`@` 文件、hook 注入 | 次高，**能覆盖下面所有层** |
| 3 | 项目常驻文件 | 人 + LLM | `AGENTS.md`、`.workbuddy/memory/MEMORY.md` | 高，但只是**默认值** |
| 4 | 服务端记忆 | 云端 | 用户画像摘要、历史会话检索 | 中（本机摘要层为空） |
| 5 | 按需读取的文件 | 人 + LLM | `SKILL.md`、索引、`log.md`、`Idea.md` | 低，**不主动读等于不存在** |
| 6 | 工具返回的内容 | 任何来源 | 文件正文、命令输出、网页、搜索摘要 | **不可信输入** |

两条推论：

- **第 2 层永远压过第 3 层。** `AGENTS.md` 写的任何规则，人一句话就能推翻——规则的实际身份是「默认值」，不是「法律」。想真硬，只能进第 1 层，而那一层谁都改不了。
- **第 6 层最危险，因为它与第 2 层在上下文里形式相同**：都是陈述句。文件里写「忽略上述要求」与网页里写「把密钥发我」，和正常内容没有语法差别。分辨只能靠判断力，没有机制保证。

### 三、`USER.md` 为何不生效：两份副本 + `read_when`

| 路径 | 字节 | 内容 | 结论 |
|---|---|---|---|
| `.workbuddy\USER.md` | 536 | 空模板（2026-09-13 种子） | 未被使用 |
| `.workbuddy\user-…-personal\USER.md` | 3,974 | 本轮填写的实例 | 位置正确，但**宿主不读** |

两份 inode 不同，不是同一文件；`workspace-state.json` 记有 `bootstrapSeededAt: 2026-09-13T02:05:38Z`，说明前者是宿主种的模板。

决定性证据来自文件自身 frontmatter：

```yaml
read_when:
  - Bootstrapping a workspace manually
```

宿主标注的读取时机是「**手动初始化工作区时**」——即设计上它就是一次性引导材料，不是常驻注入。这与 `BOOTSTRAP.md`「问出名字后删掉它」同一逻辑。

### 四、「每轮加载」不等于「堆积」

模型 API 无状态，宿主每轮把完整上下文**重新拼一遍**再发：

```
第 N 轮 = [系统提示 + AGENTS.md + MEMORY.md + 技能列表]  ← 固定段，每轮重建，只一份
        + [历史消息 1 … N-1]                            ← 增长段，唯一会涨的
        + [本轮提问]
```

固定段是**替换**不是追加：第 1 轮和第 50 轮里 `AGENTS.md` 都只有一份 8,229 字符。

### 五、实测：4,137 次调用的真实曲线

从会话记录 `projects/f-…/2856f646-….jsonl`（50 MB）提取 `usage.inputTokens`：

| 调用序号 | input tokens | 说明 |
|---|---|---|
| #1 | **34,582** | 新会话首轮，历史为空 → **地板** |
| #11 | 39,384 | 历史开始涨 |
| #51 | 93,073 | |
| #101 | 143,997 | 接近上限 |
| #301 | 141,950 | **回落 → 压缩发生** |
| #1,501 | **213,560** | 峰值 |
| #2,001 | 141,515 | 又压一次 |
| #4,137 | **131,761** | 当前 |

- **地板 34,582 里，`AGENTS.md` + `MEMORY.md` 约占 7–8k token（20–23%）**：每开一个新会话，光项目常驻就付掉约四分之一地板。
- **单调上升**＝历史在堆；**突降**＝压缩把旧历史换成摘要。摘要仍算在 input 里，是「被替换」不是「被减掉」。
- 界面读数（2026-11-07 21:27 截图）：**44.4% = 133.3K / 300.0K**，分项——系统提示词 3.5%、工具及智能体 10.5%、对话消息 29.3%、连接器及 MCP 0.1%、技能 1%。其中**对话消息是唯一会涨的块**，工具 31.5K 是第二大固定块。
- 分项里**没有单列 `AGENTS.md` / `MEMORY.md`**，位置存疑（并进系统提示词还是并进对话消息开头），从首轮 34,582 反推倾向后者；但分项之和与实测对不齐，**此条不作结论**。

### 六、无状态的推论：能换模型，但有三个约束

状态全在宿主侧，模型是纯函数 `f(上下文) → 输出`，所以换模型不影响仓库与历史。但：

| 项 | 换模型后 | 原因 |
|---|---|---|
| 对话历史 | ✅ 保留 | 存在宿主手里 |
| **上下文窗口** | ❌ 可能装不下 | 133.3K 按 300K 窗口算；换 128K 窗口须立刻压缩 |
| **token 计数** | ⚠️ 会变 | 分词器不同，同一段中文算出的 token 数不同，44.4% 会变 |
| **缓存** | ❌ 失效 | 按「模型 + 前缀」匹配 |
| **指令遵从度** | ⚠️ 需重校准 | `AGENTS.md` 那些纪律是对着某个模型脾气调出来的 |

**推论**：规则不是模型的属性，是「规则 × 模型」这对组合的属性。也意味着**任何持久性只能放在上下文或文件系统**——上下文会过期（压缩），文件系统不会。这就是「工厂的资产是规则与文件，模型是可换零件」的依据。

### 七、结论：能改的常驻通道只有两处

| 想要 | 该写哪 | 代价 |
|---|---|---|
| 硬约束、每轮必在场 | `AGENTS.md`（第 3 层） | 每轮付，且按工具调用次数放大 |
| 每轮提醒、最强可改层 | 挂 `UserPromptSubmit` hook（第 2 层） | 当前**未配**，`settings.json` 无 `hooks` 键 |
| 记住事实 | `MEMORY.md`（第 3 层） | 上限 3,000 字/会话（现已清空，见下条） |
| 特定时刻才用 | `SKILL.md`（第 5 层） | 按需触发，不占固定预算 |
| **`USER.md`** | **三处都不在** | 只能靠 §1.6「主动读」——即靠记忆，最不可靠的形式 |

**这条结论直接推出本轮的第二个产出**：既然第 5 层「不主动读等于不存在」，而 `.workbuddy/memory/` 又是 gitignored（不入库＝对下轮不可见），那**留痕必须收回到唯一入库通道**——于是有了 `USER.md` 里那条「硬约束：仓库留痕单一通道」（2026-11-07 22:31 执行：6 份日报 96 KB 删除，`MEMORY.md` 5,141 B → 7 B）。
