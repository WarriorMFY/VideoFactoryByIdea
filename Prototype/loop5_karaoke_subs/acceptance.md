## v1 → v2：抖动修复前后（同一判据，全片逐帧）

| 指标 | v1（已交付过） | v2（当前） |
| --- | --- | --- |
| 闪断（英文行整行消失） | **30 帧 / 16 组** | **0 帧 / 0 组** |
| 高亮缺失（该亮未亮） | **80 帧 / 37 组** | **0 帧 / 0 组** |
| 句内位置跳 | 0（跨句 **45 次，最大 55px**） | 0（跨句 4 次，18px＝不同句行数差异） |

三个根因与修法：

1. **词事件之间有空档**（最长 0.2s）→ 英文行整行消失几帧：改成**无缝铺砖**（每个 tile 延伸到下一个 tile 开始）。
2. **极短词高亮等于没亮 + 高频跳色**（ASR 把 LUFS 听成 `l u f s`）→ **同行内**短词合并（`--merge-word 0.18`，单双字母强制合并，不跨行）。
3. **中文随英文行数上下移动** → 中文位置改**全片固定**（`--zh-margin-mode fixed`，按最大英文行数算一次）。

数据文件：`case_E_l2_karaoke/flicker_before_fix.json`（v1）与 `flicker.json`（v2）；F 用例见 `case_F_real3_karaoke/flicker.json`。

## 判据说明

| 检查 | 阈值 | 含义 |
| --- | --- | --- |
| `highlight_present` | 每个采样帧都能检出高亮色像素 | 字幕真的上了色 |
| `single_block_per_frame` | 高亮块间最大空隙 < 200px 且总宽 < 480px | 没有"相距很远的两个词同时亮"的重影（同行的短词合并会产生连续块，属设计行为） |
| `highlight_moves` | 重心位移 ≥ 12px | 高亮跟着语流走，不是死亮一个词 |
| `no_blink` | 连续 ≥2 帧整行缺失 = 0 | 字幕不闪断（单帧 33ms 不计） |
| `no_hl_missing` | 连续 ≥2 帧高亮缺失 = 0 | 高亮不断档 |
| `no_position_jump` | 句内文字块上下边界位移 > 4px 的次数 = 0 | 同句内不跳动（跨句行数变化属正常排版） |

## 抖动诊断的取样口径（踩过两次坑）

- **必须隔离画面**：直接在成片上扫像素会把 BBB 的草地/白云当成白字（白字中位数被抬到 2312px），实测误报 29 帧闪断。诊断脚本默认把同一 ASS 烧到**纯黑底**上再测。
- **"应显示"范围用中文整句区间**：若用英文事件并集，词间空档本身被排除在统计外，恰好漏掉最大的抖源。
- **位置跳要用"文字块上下边界"**：白字质心会随"哪个词被上色"漂移（高亮词从白变青 → 白字减少），实测误报 14–18px。
