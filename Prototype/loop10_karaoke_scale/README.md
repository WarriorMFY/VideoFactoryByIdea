# 小循环 10 · 逐词高亮（karaoke）在 49 分钟长片上的规模验收

> 一句话：**1030 条 ASS 事件 / 103KB / 生成 0.1 秒**，libass 吃下整片 ASS 无压力，像素抽检 12/12 帧高亮都在。
> 顺手把一个口径说清楚：**事件数 ≈ 识别词数**（约 0.8–1 事件/词），不是"平方级爆炸"。

## 1. 为什么补这一轮

小循环 5 只在 90s 片段上验过"像素级正确"；小循环 9 的 49 分钟压测没测逐词高亮。
而 ASS 事件数是 libass 的**压力点**：事件一多，烧入会变慢甚至卡住 —— 这是"只有长片才看得出来"的问题。
所以这轮专门补：**长 ASS 能不能生成、能不能被 libass 正常烧、事件规模是否合理**。

## 2. 做法（不重复烧 49 分钟）

1. 拿小循环 9 的 273 条字幕 + EDL，生成覆盖全片的 ASS（带剪辑重映射），量事件数/体积/耗时；
2. 只烧**前 120 秒**做像素抽检（时间轴一致，直接取窗口），给 verify_karaoke 一份"只含前 120s 事件"的 ASS 副本
   （否则抽样点会落在视频之外，导致误判）；
3. 跑 `verify_karaoke`：高亮存在 / 单块不重影 / 重心随语流移动。

## 3. 结果

| 检查 | 数据 |
| --- | --- |
| ASS 生成 | **0.1s**（1030 事件、2 个样式、103KB） |
| 事件密度 | **3.8 事件/条字幕**，≈0.8–1 事件/词 |
| 时间轴覆盖 | 3.6–2841.6s（全片），峰值 **1 事件/秒** |
| 120s 烧入 | ✅ 7.8MB，libass 正常 |
| 像素抽检 | ✅ **12/12 帧**有高亮、12/12 单块不重影、重心位移 280px（确实在跟着词走） |

### 口径修正（重要）

小循环 5 里写过"1h ≈ 1–1.5 万条"，那是**按对话密集素材估的上限**。本轮实测：

- 本片对白稀疏（49 分钟只识别出上千词）→ **1030 事件**；
- 事件数基本跟随**词数**（l2 教学片：101 词 → 78 事件；本片：约 1300 词 → 1030 事件）；
- 按 ≈1 事件/词 外推，**对话密集的 1 小时片子（约 9000 词）≈ 8–9k 事件**，仍在万条以内，且是**线性**增长。

## 4. 怎么复现

```powershell
.\Prototype\loop10_karaoke_scale\reproduce.ps1
```

依赖小循环 9 的产物（`History/runs/l9_long/{subs/cues.json,cut/edits.json,cut/final.mp4}`），
先跑 `node Tool\acceptance\run_long_acceptance.mjs` 即可。整轮约 1 分钟（只烧 120s）。

## 5. 限制

- 只烧 120s：像素级正确性在小循环 5 已全量验过，这里验的是"长 ASS 能被 libass 吃下 + 规模合理"；
- 长片的逐词时间仍来自 ASR，识别错的地方高亮也会错（见小循环 7 的结论）；
- 峰值事件密度 1 条/秒说明这份素材对 libass 压力很小；对话密集素材（多词快速交替）压力会更高，
  但没有看到"事件数爆炸"的结构性风险。
