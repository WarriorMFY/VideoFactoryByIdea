# History/publish/bilibili/track — 已发布作品市场状态跟踪

机器数据（快照/报告）由 `Tool/ops/track_bilibili.mjs` 自动产出；**人读洞察层在 `insights.md`**。

## 目录约定

| 文件 | 来源 | 说明 |
| --- | --- | --- |
| `account.json` / `roster.json` | 工具枚举 | 账号档案 / 作品清单（每次 run 覆盖，最新为准） |
| `snapshots/<时间戳>.json` | 工具打点 | 单次全量打点，**历史文件不改不删** |
| `snapshots/index.jsonl` | 工具追加 | 每次打点一行的账号级汇总 |
| `report.md` / `report.json` | 工具生成 | 最近一次 vs 上一次的增量报告（会被下次覆盖） |
| `latest.json` | 工具生成 | 最近快照副本 |
| **`insights.md`** | **每轮小循环手写** | **市场感知日志，只增不删**，历史报告被覆盖后事实仍留在这里 |

## insights.md 只增不删规则

- 每轮跟踪在小循环结束时追加一节（`## YYYY-MM-DD HH:mm · 第N次`），不修改、不删除历史小节
- 写「数字」之外还要写「判断」：头部/尾部作品、冷启动状态、异常稿件、待人决策事项
- 判断必须能追溯到当次快照（标注快照时间戳）；接口取不到的字段不估算
- 若与上一节结论冲突（如某片放量、某片停滞），显式写出「较上次」的变化，便于日后回看趋势

## 跟踪关键设计（沿用 S9）

枚举需登录，打点免登录——登录态过期不阻断日常打点，只阻断发现新作品。
新作品发布后必须先重枚举再打点，否则旧清单不含新 BV。
