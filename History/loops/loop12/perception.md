# 小循环 12 · 感知（市场 ↔ 工厂 闭环验证）

## 本轮目标（人给的）

> "启动一轮循环，目的是验证'市场 <-> 工厂(这里)'整个链路是否能打通：
> 侦查 B 站上当前比较火的、而且当前工厂技术能力可以快速达到的视频 → 工厂开工制作 → 交付市场并持续跟踪反馈 → 持续迭代"

也就是说，这一轮不追单点技术指标，验证的是**链路**：
**能不能看到市场 → 能不能挑对题 → 能不能做出来 → 能不能交出去 → 能不能根据反馈再改**。

## 开工前的已知条件

| 条件 | 状态 |
| --- | --- |
| 市场数据通道 | **未知**（本沙箱只验证过少数域名能出网）→ 第一步必须实测 |
| 工厂能力 | 知识型英语视频 → 中英双语字幕（含逐词高亮、标点、术语/单位规范、人工校对回写）；49 分钟长片可跑 |
| 交付通道 | **没有 B 站账号**，工厂不代登录 → 只能做到"交付包就绪 + 上架清单" |
| 反馈数据 | 需要真实上架后才有 → 本轮的交付物是"机制可运行"，不是"数据好看" |
| 素材版权 | 不能用 B 站上的"搬运"内容再分发 → 样片必须用可授权素材（CC-BY 画面 + 合成语音） |

## 关键未知（本轮要回答）

1. B 站公开接口在这个沙箱里能不能直连？拿得到 榜单/搜索/时长/互动 吗？
2. 用什么样的**可计算指标**判断"这题我们能快速做"？（不能靠感觉）
3. 从"选题"到"可发布成片"这条链，缺哪些环节？（封面/文案/标签/分区/合规/上传清单）
4. "交付之后"怎么变成可执行的迭代动作？没有真实数据时能不能不编？

## 判据（先在动手前定好）

- A 侦查：≥60 条榜单样本 + 若干关键词市场数据 + 候选打分排序（有分数、有依据）；
- B 开工：产出一条**可发布**成片（h264/720p/质检不 FAIL/双语字幕 100% 覆盖/逐词高亮存在），识别 WER ≤15%、覆盖 ≥95%；
- C 交付包：文案（标题/简介/标签/分区）、封面、合规声明、上传清单、反馈采集表齐全；
- D 反馈：空数据时必须输出"待采集"；规则模式能给出 P0/P1 动作（自检用明确标注的合成数据）。
