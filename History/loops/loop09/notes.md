# 小循环 9 · 过程笔记（49 分钟压测 + 术语审计）

## 一句话

49 分钟的片子**能跑通、能出片**（48.7 分钟成片，273 条字幕），成本主要在两次渲染（约 22 分钟）+ 识别（约 6.5 分钟）；
长片规模下**暴露并修掉了 2 个短片样本永远不会暴露的 bug**（回写 trim、机翻脏数据）。

## 冷跑（首次）真实耗时

| 阶段 | 耗时 | 备注 |
| --- | --- | --- |
| 拼长素材（`-stream_loop` + `-c copy`） | **2.5s** | 1420MB，几乎不耗时 |
| 识别（49 分钟音频，Vosk 小模型） | **≈ 6.5 分钟** | 1091 词 / 286 段 / 置信 0.854 |
| 剪辑 + 出片（第一遍，640×360） | **675s（11.3 分钟）** | analyze + 分段 + 合并 + 收尾（drawtext/loudnorm/encode） |
| 标点恢复 + 断句排行 + 机翻（273 条） | 数分钟 | 机翻占大头（MyMemory 逐句，有缓存） |
| 重映射 / 导出校对表 / 回写 / 术语审计 | **每个都是 0.1s 级** | 273 行 CSV，回写 74ms |
| 烧入字幕出片（第二遍，640×360） | **≈ 11 分钟** | 与第一遍同一条渲染链，只多烧字幕 |
| 质检（EBU R128 + 黑场/冻帧扫描） | **57s** | |

结论：**文本层操作全是秒级，时间全在"识别"和"两次渲染"上**。要提速只有三条路：跳过第一遍渲染（拿 EDL 不渲染）、
换更快编码器（NVENC 本机没有）、或只在最终成片上烧一次（现在的流程必须两遍，因为字幕要跟着剪辑结果走）。

## 长片暴露的两个 bug

### 1) `apply_review` 会 trim 译文 → 恒等回写失败（279 行里 6 行）

第一版写回时用 `String(cell).trim()`，结果这些行的译文对不上：

| 行 | 机器产出（原样） | trim 后 |
| --- | --- | --- |
| 54 | `" Id"` | `"Id"` |
| 59 | `" <strong>%2$s</str"` | `"<strong>%2$s</str"` |

"恒等回写"是校验闭环正确性的基石（导出→不改→回写必须逐字节一致），一行 trim 就把它破坏了。
修法：**只判"是否空白"，不 trim 后写回**。修完 273 行规模下 cues 与 SRT 哈希全部一致。

### 2) MyMemory 偶发返回脏数据

同一个 `While.` 被翻成 `" <strong>%2$s</str"` 这种服务端模板残留；还有带前导空格、`%2$s` 占位符的结果。
短片样本（13 行）里一次没踩到，长片 279 行踩到 6 行 —— 典型的"规模才暴露"。

修法：`make_subs` 加 `cleanMt()`：去标签（含被截断的半截标签）、解常见实体、删 printf 占位符、折叠空白；
并把"几乎只剩模板符号"的结果视为失败重试。修完复查：279→273 行字幕里 `<>`/占位符/多余空白 **0 行**、空译文 **0 行**。

## 术语一致性审计（新增）

`export_review` 现在会拿术语表反查：

- `term_missing`：英文里出现 `LUFS`/`Mbps` 等规范术语，中文里找不到 → 最常见就是**被行宽切行切断**；
- `term_variant`：译成术语表里记录的错法（如「卢夫斯」）。

回归用例就是小循环 8 里人工修掉的那个毛病：l2 精译版把 `−16 LUFS` 切成 `…−16 LU` + `FS，…`。
审计在 CSV 里标出 `term_missing`，并给出 `review.json → term_audit` 的统计（出现几行、规范/错法/缺失各几行）。

## 质检 WARN 的三个已知原因（不是链路问题）

| 项 | 数值 | 阈值 | 说明 |
| --- | --- | --- | --- |
| 真峰 | −0.7 dBTP | ≤ −1.0 | 这部片子的混音响度较高，归一后峰值仍偏热 |
| 残留黑场 | 2 段 | 0 | 片子本身的黑场（语音保护+黑场阈值收紧后仍留 2 段） |
| 音画差 | 0.1s | < 0.1 | 临界（帧对齐余量） |
