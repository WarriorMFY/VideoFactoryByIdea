# 能力包交付校验清单

> 逐条执行，任何一条不过都不算交付。全部通过后，把结果抄进交付说明。

## A. 结构

- [ ] 目录树与设计稿逐项对齐，没有"顺手多建"的目录
- [ ] 只有一个代码目录，脚本没有散落在根
- [ ] 样例目录里 spec / 元数据 / 视觉基准三样齐全
- [ ] 根目录只有约定文件与约定目录

## B. 构建

- [ ] 构建脚本按清单复制，缺文件时**报错退出**而不是跳过
- [ ] `--clean` 后重建，产物与上次一致（无残留、无漏拷）
- [ ] 新写的文档来自 `seed/`，不是在产物里手改的
- [ ] 机器产物里的绝对路径已被改写为包内相对路径

## C. 校验

- [ ] 必需文件计数通过（数出来的，不是"存在即通过"）
- [ ] 所有可执行文件过语法检查
- [ ] 路径泄漏扫描零命中（源仓库名、盘符路径、用户名路径都要扫）
- [ ] 依赖四类在位：二进制 / 动态库 / 模型 / 运行时包
- [ ] **反向验证**：故意删一个必需文件，校验脚本必须变红

## D. 冒烟

- [ ] 在**包内**、脱离源仓库执行主链路
- [ ] 产出时长与随包样例一致（差值 < 0.1s）
- [ ] 客观质量指标落在合格基线内
- [ ] 抽帧目检通过（结构元素齐全、无黑帧、无乱码）
- [ ] 冒烟产物保留作为证据，临时素材已清理

## E. 文档

- [ ] 根 README 能在 30 秒内说清"能干什么 + 怎么跑第一条命令"
- [ ] `Tool.md` 只给最短路径，不是脚本全表
- [ ] 边界文档写明授权状态与不可做的事
- [ ] 样例 README 有规格表与复现命令
- [ ] 文档里的命令**复制到终端能直接跑**（路径、参数都对）

## F. 交付说明

- [ ] 包体积与构成（代码 / 样例 / 依赖各占多少）
- [ ] 依赖策略写明（随包 or bootstrap，各需要什么网络条件）
- [ ] 未入包的内容与原因（版权、体积、需账号）
- [ ] 遗留缺口与接手方式（哪些步骤仍需人工）

## G. 版本控制（若交付方要求）

- [ ] 新目录 `git init` 后 per-repo 配了提交身份
- [ ] `.gitignore` 生效：大件未入库，样例关键文件**确实入库**
- [ ] 首提交后核对远端分支 SHA 与本地一致
