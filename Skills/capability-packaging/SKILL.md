# 能力打包迁移

把一个"在源仓库里能跑"的能力，变成"拷到别处也能跑、能重建、能被质疑"的目录包。

**这个技能故意不含工具实现。** 方法论留在这里，可执行的东西留在 `Tool/`，构建与校验脚本留在 `Prototype/`。
引用一律写仓库内路径，禁止把脚本、依赖、素材复制进 `Skills/`——复制即分叉，分叉立刻开始腐化。

## 什么时候用

- 用户说「把某个能力打包/迁移出去」「导出一个独立包」「做个能拷走的东西」
- 某条链路已经跑通并沉淀进 `Tool/`，需要交付给别人或换机器复现
- 想把一段探索成果固化，避免下次从零摸索

**不适用**：只是想让别人看懂代码（写文档即可）；只是备份（`git push` 即可）。

## 三条硬判据

打不出这三条，就还不是一个包，只是一堆文件：

| 判据 | 具体含义 | 怎么验 |
| --- | --- | --- |
| **能独立跑** | 目标机从零 bootstrap 后，核心命令一条跑通 | 在**包内**、脱离源仓库跑一遍主链路 |
| **能重建** | 有构建脚本，随时从源仓库重新生成，不靠手工复制 | `--clean` 后重跑构建，产物一致 |
| **能被质疑** | 有校验脚本 + 冒烟报告，指标与源仓库对照 | 校验脚本绿灯 + 冒烟指标落在合格基线内 |

## 流程七步

### Step 0 · 界定能力边界

先写一句话产出，再倒推步骤表。

> 「输入 __，输出 __，中间 __ 步。」

步骤表每行必须填：**步骤 | 工具（仓库路径）| 输入 → 输出**。
判定某步该不该进包的唯一标准：**删掉它，最终产出还在不在？** 在 → 它是支线，不进包。

同时列出**隐式依赖**，这是最容易漏的：字体、模型文件、浏览器内核、登录态、外部 API、许可证状态。

### Step 1 · 依赖盘点

从入口脚本追 `import`，把被多个入口共用的抽成一层（`lib/`）。然后反向确认：

- 每个"被复制进包"的文件，都被谁 import？（无人 import 的文件不要进包）
- 每个 import 出去的东西，是否都在包内或由 bootstrap 装？（漏一个，包就启动不了）

隐式依赖单独列一张表，写清"从哪来、多大、能不能重建"。

### Step 2 · 文件取舍

按四象限切，不要按目录切：

| 进包 | 不进包 |
| --- | --- |
| 可执行代码、配置、术语表 | 过程产物、调试输出、`.work/` 中间件 |
| 稳定文档（README / Tool.md / 坑位清单） | 缓存、下载临时文件 |
| 一个完整样例（spec + 元数据 + 视觉基准） | 全部历史样例、全部成片 |
| 能力来源档案（为什么这么做） | 其他轮次的无关档案 |
| 依赖：二进制/模型/包（决策点 ①） | 素材源片（版权 + 体积，通常改由抓取脚本重建） |

**体积先算再动手**：立项时就把每类文件的体积量出来，包的目标体积写在计划里。否则会在拷到一半时才发现方向错了。

### Step 3 · 目录设计

镜像源仓库的**形状**，不镜像它的**层级**：

```text
包名/
├── <入口文档>            原样搬（约定与规则）
├── README.md             新写：能力全景 + 30 秒上手 + 边界
├── <边界文档>            能力边界与授权红线（仅用户可写的那份，代拟稿要标注）
├── Tool/                 唯一代码目录（按功能分目录，每目录一份 .md）
├── Prototype/sample_*/   一个完整样例，带复现命令
├── History/              能力来源档案 + 循环日志模板
└── Workspace/            deps/ 缓存/ 运行态（可清空重建）
```

三条约束：

1. **一个代码目录**，别把脚本散落在根上；
2. **样例要能"看懂 + 重跑"**，不只是能看——spec、元数据、视觉基准三样齐全；
3. **文档分层披露**：根 README 只回答"这能干什么、怎么上手"，细节进子目录 `.md`。

### Step 4 · 文档四件套

| 文档 | 必须回答 | 常见失败 |
| --- | --- | --- |
| 根 README | 能力是什么 / 输入什么出什么 / 30 秒怎么跑 / 边界在哪 | 写成了安装手册 |
| Tool.md | 三到五条最短路径（复制即用） | 罗列了全部脚本，没告诉人先跑哪条 |
| 边界文档 | 授权、内容红线、不可做的事 | 漏写，交付后立刻踩雷 |
| 样例 README | 这条样例的规格表 + 章节清单 + 复现命令 | 只放文件，不讲怎么复现 |

### Step 5 · 构建脚本化

构建脚本进 `Prototype/`，不进产物包。硬性要求：

- **清单驱动**：要复制哪些文件写在数组里，逐条 `copyFile`，缺一个就报错退出
- **幂等**：`--clean` 先删产物目录再建，允许反复跑
- **路径改写**：机器产物的 JSON / 日志里若有源仓库绝对路径，复制时正则为包内相对路径
- **种子文档独立存放**：新写的文档放 `seed/`，构建时原样搬进去——保证包可重建，不用手工维护两份

### Step 6 · 校验脚本化

校验脚本与构建脚本同目录。四类检查，缺一类都不算过：

1. **必需文件**：清单里每个文件在位（数量要对，不是"存在即通过"）
2. **语法**：所有可执行文件过一遍语法检查
3. **路径零泄漏**：正则扫全文，源仓库路径、盘符绝对路径必须零命中
4. **依赖在位**：二进制、动态库、模型、运行时包逐个确认

> 校验脚本自己也会骗人：正则写宽了（只查一个关键词）等于没查；文件计数写成 `existsSync` 等于没查。写完先故意造一个"坏包"验证它会红。

### Step 7 · 包内冒烟 → 交付

冒烟必须在**包内**、**脱离源仓库**跑，否则验证的是源仓库。

1. 用包内样例 spec 重跑主链路
2. 产出与随包成片的**客观指标**对照（时长差、质量指标、抽帧目检）
3. 清理临时素材，把冒烟产物留作证据
4. 交付时给三样：目录结构树、校验结果、冒烟数字

## 三个必须让人拍板的决策点

打包前一次性问清，不要边做边猜：

| 决策 | 选项差异 | 影响 |
| --- | --- | --- |
| ① 依赖随包 or bootstrap | 随包几百 MB 秒开；bootstrap 包小但要联网 | 决定包体积与"离线可用"承诺 |
| ② 样例带多少 | 只有 spec / 加摘要成片 / 加成片全带 | 决定包体积与"开箱即见效果" |
| ③ 缺口补不补 | 补工具（多一条命令）/ 只文档化手工步骤 | 决定包是否真闭环，还是把手工步骤甩给接手的人 |

默认建议：bootstrap + 只带 spec 与视觉基准 + 补齐缺口。若要偏离，让用户明说理由。

## 坑位（都会静默失败）

1. **绝对路径藏在机器产物里**：JSON 元数据、运行日志、报告里写死了源路径，源码 grep 干净但包里仍在泄漏。修法：构建时改写 + 校验时全文扫。
2. **`.gitignore` 静默吃掉样例**：成片、帧图被忽略规则挡住，"构建成功"但内容不在仓库里。修法：校验要数文件数，并核对关键样例文件确实被跟踪。
3. **在源仓库里冒烟**：路径能解析、依赖能找到，一切正常——但验证对象错了。修法：冒烟一律 `cd` 到包内跑。
4. **样例缺视觉基准**：只给 spec 不给"应该长什么样"，接手的人跑出来也不知道对不对。修法：随包带抽检图/封面，冒烟时对照。
5. **提交身份缺失**：目标目录新 `git init` 后首个提交直接失败（全局没配 `user.name`）。修法：per-repo 配身份，沿用源仓库一致的名字。
6. **网络抖动被当成权限问题**：推送 502/超时，容易误判为鉴权失败。修法：先用 `curl` 打同一端点看状态码，再决定重试还是查凭据。
7. **文档写成了实现**：把脚本片段抄进 README，两份立刻分叉。修法：文档只写「跑哪条命令」，实现改动只改 `Tool/`。

## 完成判据

逐条打勾才算交付，细则见 [`references/checklist.md`](references/checklist.md)：

1. 步骤表完整，每步有工具与输入输出
2. 目录结构与设计一致，无多余层级
3. 构建脚本 `--clean` 可重建，产物一致
4. 校验四类全绿，且验证过"坏包会红"
5. 包内冒烟跑通，客观指标落在合格基线内
6. 四件套文档齐全，30 秒上手路径可复制即用
7. 路径零泄漏（含机器产物）
8. 体积、授权边界、遗留缺口三项写进交付说明
