# talk-loop — 名人演讲双制品全链路

> 本 Skill 只写**方法论**：阶段划分、判据、决策规则、反模式、参数约定。
> 所有工具以 `Tool/` 下的路径引用，不复制实现；工具行为以源码与该目录 README 为准。

## 0. 何时用 / 何时不用

**用**：手上有一条 10–20 分钟的名人演讲（TED / 峰会主舞台），要在一次循环内产出
「完整长片 + 3 分钟摘要」两个成品并发布，且两者要互相导流。

**不用**：
- 只要切片不要摘要 → 跳过 S4–S5，直接 S6 起；
- 无官方中文字幕且不允许人工精译 → 见 S1 的降级判据，通常本轮应换片；
- 批量补建已发布作品缺失的摘要 → 走 `History/loops/loop14/publish_log.md` 记录的批量模式，不走本流程。

**三条红线（先确认再动手）**：素材许可（TED 为 CC BY-NC-ND 4.0，仅非商业）、
发布动作必须由人显式发起、解说文案必须原创（不得搬运他人解说）。

## 1. 核心方法论

### 1.1 一条竖切，两个制品

长片是**内容资产**（完整、可被检索、值得收藏），摘要是**分发入口**（低门槛、可被推荐）。
两者不是主次关系，是**互相的入口**：摘要末尾指向长片，长片置顶指向摘要。
所以"只发一条"永远不算闭环——判断标准是 **两个制品 + 双向导航**同时在线。

### 1.2 阶段顺序不可颠倒

```
探字幕 → 定片 → 素材入袋 → 长片 → 质检 → 长片发布(拿 BV) → 摘要 → 质检 → 摘要发布 → 双向导航 → 留痕/打点
```

三条硬顺序，颠倒就返工：

1. **先探字幕再定片**。中译可用性决定整条链路成本：有官方 `zh-cn` 就是"直灌"（分钟级），
   没有就要全篇精译（小时级 + 质量风险）。先选片后探字幕 = 选完才发现要自译。
2. **长片先于摘要**。摘要在用长片的源片帧位与对齐结果，且**摘要片尾卡要写长片 BV 号**——
   没 BV 就得渲染两遍。
3. **质检先于发布**。发布后不可逆的只有"下架"，但错误已在观众侧暴露过一轮。

### 1.3 并行纪律

渲染是长任务（长片 7 分钟、摘要 4 分钟），必须后台跑；前台同时做下一阶段的**纯写作/纯探测**工作：
长片渲染时写摘要稿 + 起封面、摘要渲染时写简介 + 生成置顶评论。一轮的总时长 ≈ 最长串行链，
不是各阶段之和（实测 31 分钟闭环，串行需 45+ 分钟）。

## 2. 九阶段：目标 / 判据 / 失败处理

### S1 选片（目标：一条讲者有名、主题贴合、中译可得的最新演讲）

探测方法：TED 列表页的 `__NEXT_DATA__` 里 `props.pageProps.talks` 可直接拿到结构化清单
（`www.ted.com/talks?sort=newest`、`www.ted.com/topics/ai?sort=newest` 同构），无需爬 DOM。
talk 页里的 pm id 从 `hls.ted.com/project_masters/<id>` 提取，字幕可用性看
`hls.ted.com/project_masters/<pm>/subtitles/zh-cn.m3u8` 是否 200。

四维判据（按权重）：
1. **官方中译可得**（一票否决项，缺则成本翻倍）；
2. **讲者知名度**（是否公众人物 / 是否有"头衔可写进标题"）；
3. **主题与频道定位一致**（AI、科技、互联网治理等）；
4. **新鲜度 + 时长**（10–20 分钟最佳；< 8 分钟做摘要太薄，> 20 分钟长片太重）。

实测数据用于校准预期：TED「最新 24 条」里仅 1 条带官方中译；「AI 主题 16 条」里仅 4 条——
**不能假设大咖必有中译**（Reed Hastings、Sal Khan 都没有）。若候选池全无中译，先问人是否接受自译。

失败处理：候选池无合格片 → 扩大探测面（换主题页 / 往回翻页）→ 仍无则降级为"无中译"分支并明确告知成本，
不得默默自译后当成"官方直灌"记录。

### S2 素材入袋（目标：视频 + 双语 cue 一次到位）

校验三件事，缺一不可：视频时长（与列表页 duration 偏差 < 2s）、英文 cue 数、
**中文 cue 数**（为 0 说明中译探测判断错了，立刻回 S1）。产出落到 `Workspace/tmp/<ep>/`。

### S3 长片渲染（目标：一条命令产出成片）

关注三个中间信号，它们是后续阶段的输入质量：
- ASR 词数 + 置信度（低于 ~0.9 说明音轨或切片有问题）；
- 时间轴偏移标定量（> 5s 要怀疑源片有片头/台标偏移）；
- **中译命中率**（应接近 100%；漏词意味着时间轴或分句错位，必须修好再往下走）。

判据：命中率 < 99% 视为不合格——长片是资产，不能带着缺字上线。

### S4 写摘要稿（目标：30 段解说 × 7 章，每段锚到原片帧位）

方法论顺序：**先读全文分桶 → 再选帧 → 再写稿**。反过来（先写稿再找画面）会出现"讲的东西画面里没有"。

- 分桶：按 45 秒切原文（双语对照），一桶 ≈ 一段解说，控制信息密度；
- 选帧：先全片均匀抽帧看整体覆盖率，再对候选帧位精抽复核，确认无黑帧/纯色转场/全暗画面；
  帧位用"原片秒数"，不要用"摘要秒数"（摘要时间轴由 TTS 决定，写稿时还不存在）；
- 结构：30 段左右分 7 章，**章节名要有叙事张力而非目录感**（"一块瑞士奶酪" > "第三部分 隐喻分析"）；
- 每段文案一条硬规则：**陈述原片说了什么，不添加原片没有的判断**；数字必须能在原片找到出处。

### S5 质检（目标：三条客观信号全绿）

1. **抖动审计**：长片 `sd ≤ 0.30` 合格；与已发布样例同一量级即可（样例基线 0.297）；
2. **目检**：抽 2–3 帧确认双语字幕齐、英文逐词高亮在跑、中文行不叠字/不乱码；摘要片另看
   片头卡、右上"原片 mm:ss"角标、片尾卡的 BV 号是否真实显示；
3. **时长回读**：文件时长与 `ffprobe` 记录一致，且与预期段数×平均语速吻合（差 > 5s 查漏段）。

任一项不绿 → 修 → 重跑，**不得"带着已知缺陷发布"**。已知缺陷若必须上线，必须先告知人。

### S6 封面（目标：一次成型）

先用**字符宽度公式**估宽再出图，避免反复试错：CJK ≈ 1.0×字号宽、latin ≈ 0.55×字号宽；
`fs=0.16` 时单行 CJK 上限约 11 字。两行标题**共用同一字号**，所以混排行（"Cloudflare CEO 说透…"）
必然溢出 → **两行都写纯中文短句**，机构/人名下沉到副标题。

版式两种，按制品选：
- 长片：左上角标（如"完整演讲"）+ 两行黄字主标题 + 底部副标题（人名 · 会议 | 字幕说明）；
- 摘要：角标固定"摘要报告"（粉色系）+ 两行主标题（第二行常为"3分钟摘要"）+ 副标题带"完整版 mm:ss"。

### S7 发布（目标：落库参数正确 + 上传完整）

参数约定（同类稿件保持一致，便于分区推荐与用户预期）：
`tid=231`（人工智能）、`htype=1011`（创作声明对应值）、`decl=含AI生成内容`、标签 6 个、
简介用文件传入（避免 shell 转义问题）。

**发布后必须回读校验**，这是硬步骤不是可选步骤：`state=0`（开放浏览）+ 线上 duration 与本地成片
差值 < 2s（证明上传完整）。出现过"表单就绪 0s"的竞态日志但实际上传完整的情况——所以
**日志信号不可作为结论，只有回读能判定**。若回读 `-404`，先查创作中心稿件状态（可能 state=-30 审核中），
不要立刻判定失败重发（会出重复稿件）。

### S8 双向导航（目标：两个方向各一条置顶）

| 方向 | 位置 | 内容 | 生成方式 |
|---|---|---|---|
| 摘要 → 原片 | 摘要片置顶评论 | 7 章跳转表：`章名 ｜ 摘要 mm:ss → 原片 mm:ss  + ?t=秒` 链接 | 从摘要 manifest 的章节表自动生成，`digest_t` 与 `src` 双时间轴都要出现 |
| 原片 → 摘要 | 长片置顶评论 | 一句话 + 摘要链接 + 一句"为什么还值得看完整版" | 固定模板，只换人名与钩子 |

要点：跳转表**必须由 manifest 生成**（手写必错位）；两条评论都要留 `rpid` 到循环日志，
便于事后核查置顶是否被平台撤下。

### S9 留痕与跟踪（目标：下一轮可复现、数据可对比）

三处留痕各司其职，不要混：
- `History/CircleLog/log.md`：一轮一条摘要（开始/结束/目标/结果/人工反馈），追加不改写；
- `History/loops/<ep>/loop_log.md`：本轮决策依据与实测数据（探测结果、命中率、返工原因）；
- 数据打点：新作品发布后立即重枚举清单再打点（旧清单不含新 BV，会用旧数据糊弄自己）。

打点之外还有第四处：**每轮跟踪结束手写追加 `History/publish/bilibili/track/insights.md`**
（市场感知日志，只增不删）——写数字之外的判断（头部/冷启动/异常稿/待人决策），规则见同目录
`README.md`。report.md 只保留最近一次增量、会被覆盖，跨轮趋势只存在于 insights.md。

跟踪的关键设计认知：**枚举需登录，打点不需要**。所以登录态过期不阻断日常跑，只阻断"发现新作品"。

### S10（可选）摘要动态：把双制品再导流一次

从已发布作品里**选数据最好的那条**（看跟踪报告，不拍脑袋），做一条图文动态：
竖版卡片（1080×1440，4 张）+ 总结性文字 + 原片与摘要双链接。判据：

- 卡片文案素材**取自该片的 digest spec**，不新写观点（口径一致，零事实风险）；
- 正文里的 B 站视频链接会被平台自动转成带标题的卡片，无需特殊处理；
- 卡片是 ffmpeg 渲染的，**禁 emoji**（SimHei 无字形 → 豆腐块）；
- 发布后回读空间动态列表确认可见，`dyn_id` 记入循环日志；
- 本地无源片时用 `ted_frame` 从 HLS 定点抓帧做卡片底图（每帧约 5 秒，不用整片下载）。

## 3. 判据总表（Gate）

| 阶段 | 通过判据 | 不通过的处置 |
|---|---|---|
| S1 | 官方 zh-cn 字幕 200 且 cue > 0 | 换片；或显式告知后走自译分支 |
| S2 | 视频时长偏差 < 2s 且双语 cue 均 > 0 | 重抓；仍缺 → 回 S1 |
| S3 | 中译命中率 ≥ 99%、ASR 置信 ≥ 0.9 | 修对齐/分句，不带着缺字上线 |
| S4 | 30±5 段、7 章、每帧位目检非黑帧 | 补抽帧重排 |
| S5 | 长片 sd ≤ 0.30、三帧目检无异常、时长自洽 | 修后重跑 |
| S6 | 标题不截断、嵌入帧未丢失 | 改文案结构（不是无脑缩字号） |
| S7 | 回读 state=0 且时长差 < 2s、tid 正确 | 查审核态，不重复投稿 |
| S8 | 两条置顶各带 rpid 回执 | 重发或手动置顶 |
| S9 | 清单含新 BV、快照落盘、日志已追加 | 补跑 |

## 4. 决策规则

1. **成本前置判断**：任何会改变工量一个数量级的选择（有无中译、长片时长），必须在动手前探明。
2. **资产优先于速度**：长片宁可多花 2 分钟修对齐，也不接受 99% 以下的命中率。
3. **一次只错一处**：封面、标题、简介这类"只看一眼就能判断"的产物，先目检再提交，别靠日志自信。
4. **可逆先行**：不确定的参数（分区、标签）先按历史同类稿件的取值走，发布后再用回读校正。
5. **不替人做减法**：删除、下架、改标题等破坏性动作一律列清单等人确认，不自行执行。
6. **失败只报事实**：频控/风控/审核都写原始 code，不写成"大概成功了"。

## 5. 反模式（踩过的坑，按代价排序）

1. **假设大咖必有官方中译** → 探测成本极低，不探就选片，可能整轮返工。
2. **把"表单就绪"当日志结论** → 唯一可信的是发布后回读 state + 时长。
3. **封面靠缩字号解决溢出** → 字号对两行统一生效，缩到能放下第一行时第二行仍溢出；改文案结构才对。
4. **先写稿再找画面** → 出现"解说讲的东西画面没有"；永远先选帧。
5. **手写章节跳转表** → 时间错位且不可复核，必须从 manifest 生成。
6. **摘要先渲染再拿 BV** → 片尾卡 BV 是硬编码进画面的，晚拿到就得重渲染（4 分钟）。
7. **发布完不重枚举清单** → 打点仍按旧清单跑，新作品"不存在"。
8. **工具引用与实现漂移** → 文档里写的脚本必须真实存在（曾出现 README 引用了不存在的脚本，
   导致"写摘要第一步"断链）；改链路时同步改文档。
