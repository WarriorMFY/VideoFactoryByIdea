# 授权与可发布

> **读到这里就够，除非**你要把素材用进要发布的成片，或者你在怀疑某条素材的授权不准。
> 字段定义 → [`字段字典.md`](字段字典.md)；分类实现 [`../../Tool/lib/license.mjs`](../../Tool/lib/license.mjs)

## 一句话

**`license_class` 决定能不能发，`tier` 只决定这次采它花了多少。** 两者没有推导关系，别用一个猜另一个。

## 类别表

| `license_class` | 含义 | `tier` | 可发布 | 处理 |
|---|---|---|---|---|
| `PD/CC0` | 公有领域 / 放弃权利 | L1 | ✅ | 直接用，仍要署名（体面，非法律要求） |
| `CC BY` | 署名即可 | L1 | ✅ | 简介里原样放 `attribution` |
| `CC BY-SA` | 署名 + 相同方式共享 | L2 | ⚠️ 可，但成片也须 CC BY-SA | 默认不用于商业成片；要用先人工确认传染范围 |
| `REVIEW` | NC/ND/合理使用/© 版权保留/研究引用 | L2 | ❌ 商用 ❌ 平台发布 | 仅限内部研究、评论引用；**B 站这类公开投稿默认落这里** |
| `UNKNOWN` | 没有授权信息 | L2 | ❌ | 先查清；查不清就不要用 |

判定是关键词匹配（见 `Tool/lib/license.mjs` 的 `RULES`），**不保证法律准确**，它的作用是"把含糊的挡在门口"，
不是"给合规背书"。写 `license` 时把看到的原话抄进去，让分类有据可依。

## 当前库的实际状态（别自我安慰）

`影之刃零` 47 条全部是 `REVIEW` + `L2`：

```json
"license": "版权归原作者 · 研究/评论引用（非商业）",
"license_class": "REVIEW",
"license_raw": "未见明确许可声明（B站普通投稿，默认版权保留）"
```

结论：**这批素材可以做研究、做评论性使用（loop43 的成片属于这一类），不适合作为商业素材库直接取用。**
真要商用，路径是换授权明确的源或换自有录制，不是改这个字段。

## 发布前怎么查（现状：手工）

机器判据已经有了，但**还没接进发布脚本**（`Tool/ops/publish_bilibili.mjs` 不做素材授权检查）。
接之前，发布前手工跑：

```bash
# 看这次要用的素材是什么授权（按 unit 号查）
python -c "
import json,sys
want={'u05','u30','u11'}
for l in open('Material/manifest.jsonl',encoding='utf-8'):
    r=json.loads(l)
    if r.get('unit') in want: print(r['unit'], r['license_class'], r['attribution'], r['path'])
"
```

判定规则（人肉版）：出现 `REVIEW`/`UNKNOWN` → 只能做研究/评论引用，成片里必须有评论性语境，简介标注出处；
出现 `CC BY-SA` → 成片须同许可；只有 `PD/CC0`/`CC BY` → 可自由发布（仍带署名）。

## 待补（有触发条件才做）

| 待补 | 触发条件 | 接入点 |
|---|---|---|
| 发布前自动 gate | 第二次因授权问题返工 | `publish_bilibili.mjs` 上传前读 cfg 的素材列表 → 查账本 → 有不可发则中止 |
| 成片 → 素材血缘表 | 同一镜头被 ≥2 个成片复用 | cfg 里的 `uNN` 反查账本，出 `History/publish/<run>/provenance.json` |
| 授权复核提醒 | 任一题材 `license_raw` 为空超 30 天 | `material_layout` 加 `W4` |

**不做的**：自动抓取版权页、LLM 判授权。授权判断错一次就是法律风险，不如让它慢一步、由人确认。
