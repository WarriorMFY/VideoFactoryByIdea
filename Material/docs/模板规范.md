# 模板规范（v1）

> **读到这里就够，除非**你要新增一类素材、要改目录形状、或质疑某条硬规则为什么存在。
> 只想入库一份新素材 → [`入库操作.md`](入库操作.md)；只想查错 → [`校验口径.md`](校验口径.md)。
> 上级：[`../Material.md`](../Material.md)｜机器可读的注册表：[`../kinds.json`](../kinds.json)

## 为什么有这一册

`Material.md` 原本把「目录树 + 7 条硬规则 + 命令 + 分级」全塞在 115 行里，读的人要一次吞完。
现在拆开：**入口只回答"读哪一册"，这一册只回答"形状该长什么样"**。

## 定版形状（v1）

```
Material/
├─ Material.md              # L0 入口
├─ manifest.jsonl           # 总账（唯一机器真源）
├─ kinds.json               # 素材类注册表（唯一机器真源，校验器读它）
├─ docs/                    # L1 六册（本目录）
└─ <题材>/
   ├─ <题材>.md              # 题材索引（人读，必写）
   ├─ 源片/                  # 本批母带，命名 <来源标识>_<短名>_<规格>
   └─ <素材类>/              # 例：处决镜头、关键帧
      └─ …                  # 形状由 kinds.json 里该类的 shape 决定
```

**两个"真源"分工**：`manifest.jsonl` 管"每条素材是什么"，`kinds.json` 管"每类素材该长什么样"。
其余文档都是这两者的解释，冲突时以它们为准。

## 三种 shape（这就是"模板"的全部抽象）

| shape | 适用 | 必备 | 校验重点 |
|---|---|---|---|
| `units` | 一源片切成 N 个**可引用单位**（处决镜头） | `uNN.<perUnit…>` + `rootFiles` | 编号连续、每单位套件齐、清单行数=单位数 |
| `files` | 无单位语义的成组文件（关键帧/音效/参考图） | 命名符合 `namePattern` + `rootFiles` | 每个文件都入账，命名不跑偏 |
| `source` | 母带 | 放 `题材/源片/`，不进素材类目录 | 命名带来源标识（BV 号或 `LOCAL<日期>`） |

新增素材类 = 在 `kinds.json` 里加一条（选 shape + 声明必备件），**不改校验器代码**。
v0 把「处决镜头」的形状写死在代码里，任何其他类一入库就被报"没有 uNN.mp4"——那是把样例当成了通则。

## 现行注册表

| 类 | shape | 必备件 | 状态 |
|---|---|---|---|
| `源片` | source | `<BV…>.mp4` 或 `LOCAL<日期>_…` | active |
| `处决镜头` | units | `uNN.mp4/.jpg/.ass` + `catalog.csv` + `index.html`，1080p60/yuv420p | active |
| `关键帧` | files | `uNN_[abc].png`，无根目录清单件 | **declared（未启用）** |

`declared` = 已声明但磁盘上还没有实体。真迁进来时校验器会告警 W3 提醒升 `active`。

## 通用硬规则（不分 shape）

| # | 规则 | 为什么 |
|---|---|---|
| 1 | 一层**题材**，一层**素材类**，不再往 `library/` 塞新东西 | 两层就到顶，再深没人翻 |
| 2 | 一个素材类目录只放**一类**东西，不混 | 混了就没法用 namePattern 校验 |
| 3 | 进目录的东西**必须入账**（`F7` 抓"手放进去不登记"） | 账本是唯一机器真源 |
| 4 | 实体搬动/改名后**必须重跑 `archive --in-place`** | 账本 `path` 就是实体位置，否则 F1 悬空 |
| 5 | 母带**上提到 `题材/源片/`**，不在每个素材类下各存一份 | 同一部源片会切出多类素材，逐类存 = 224MB × 类数 |
| 6 | 题材索引 `<题材>.md` 必写 | 人读入口，也是 F2 的判据 |

**素材类目录名用中文短名**（`处决镜头` / `关键帧` / `场景空镜`），不用英文/缩写：目录名会进账本 `kind`，中文在查询和对话里都不用翻译。

## units 型的额外规则

1. 编号 `u01 → uNN` **连续、补零、不复用**；
2. 每单位 `perUnit` 声明的扩展名必须同号同名齐备（缺一即 F3）；
3. 根目录 `rootFiles` 齐备；`catalog.csv` 行数 = 单位数（F4）；
4. `index.html` 核对页必须有（F5），视频用相对路径 `src="u01.mp4"`（换机可用）；
5. 母版规格对 `masterSpec`（W1，只告警不拦——不同类要求不同）；
6. **只登记单位母版**，`.jpg/.ass` 跟随母版不单独入账（否则账本虚胖 3 倍）。

## 为什么不给每个素材类放 `_meta.json`

之前提议过，撤回。原因：`.gitignore` 只放行 `Material/<题材>/*.md`，要让子目录里的 json 入库得改三层否定规则，
而它要记的信息（producer / 创建时间 / 批次号 / 源片引用）本来就是 `<题材>.md` 的正文内容。**能不加文件就不加。**
机器需要的那部分（shape/必备件/命名）已由 `kinds.json` 承担。

## 版本与复核点

- 当前 **v1**（2026-11-08）。v0 是"一个样板 + 7 条硬规则"，样本量 1。
- **第 2 个题材入库时，本册全部判据强制复核一遍**（样本量到 2 才谈得上通则）。复核时优先删，不是优先加。
- 改形状要升 `kinds.json.version` 并在下表留一行，旧题材不必迁移，但要标"按 vN 入库"。
