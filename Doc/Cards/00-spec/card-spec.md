# 卡片元格式规范

所有卡片 = **YAML frontmatter** + **严格两列表格**。本节是唯一权威定义，模板与实例不得自行扩展结构。

## 一、frontmatter 字段

| 字段 | 必填 | 取值 | 说明 |
| --- | --- | --- | --- |
| `name` | 是 | `<type>-<slug>` | 与文件名一致（去 `.md`）；必须 `type + "-"` 开头 |
| `type` | 是 | 11 枚举值 | 唯一类型标识，见 README 第二节 |
| `is_template` | 否 | `true` | 仅 `10-templates/` 使用；实例卡不得出现 |
| `description` | 是 | 两段式 | `介绍` ≤ 40 字；`何时使用` 以「当用户询问…时使用」收尾 |
| `source` | 否 | 数组 | `title` / `url` / `note` 三键 |
| `scope` | action 必填 | `execution` / `locomotion` / `reaction` / `interaction` | 动作作用域 |
| `level` | action 必填 | `terminal` / `control` / `incap` | 动作结果强度 |
| `ui_kind` | ui 必填 | 见 07 模板枚举 | UI 类别 |
| `severity` | anti 必填 | `blocker` / `warning` | 违反后果 |
| `references` | composite 必填 | 九槽位 | 唯一装配清单 |

除上表字段外不得新增自定义键。确需扩展，先改本规范。

## 二、description 两段式

| 段 | 写法 | 目的 |
| --- | --- | --- |
| `介绍` | 一句话，只讲本卡自身内容，不涉他卡 | 供检索时快速判重 |
| `何时使用` | 「当用户询问 X、Y、Z 时使用」 | 供 RAG 做意图路由 |

X/Y/Z 必须是外观、结构、过程层面的物理词汇，不写「想要好看时」。

## 三、严格两列表格

| 规范项 | 要求 |
| --- | --- |
| 表头 | `<轴名>（自变量：<维度>）` 竖线 `<轴名>（因变量：<描述>）` |
| 行标签 | `<对象> / <序号>`，序号从 0 递增，不跳号 |
| 单元格 | `键=值；键=值；…`，分号分隔，键序全表一致 |
| 空位 | 禁止空位、禁止「略」「同上」「等」 |
| 列数 | 严格两列；三列及以上视为无效 |
| 附加表 | 主表后允许至多两张两列表：一张定值参数表 + 一张映射或顺序表 |

## 四、硬约束

1. **零外链**：九类基础卡内不得出现其他卡名，实体一律写作角色位。
2. **角色位**：`主体A` 施动 / `主体B` 受动 / `主体<A/B>` 须指定归属，由联合卡解析。
3. **类型自证**：`type` 必须等于 `name` 前缀；冲突以 `type` 为准并驳回该卡。
4. **无审美判断词**：禁用「好看 / 英俊 / 漂亮 / 帅 / 有气质 / 高级感」。
5. **数值带量纲**：`<> mm`、`<> 帧`、`<> px`、`<>（0–1）`，不得裸数字。
6. **单一真相**：绑定关系只写在 `composite.references`，子卡不得重复声明。

## 五、通用校验

- [ ] `name` = 文件名，且以 `type + "-"` 开头
- [ ] 主表两列，行序号从 0 连续
- [ ] 单元格无空位、无「略」
- [ ] 全文无其他卡名、无审美判断词
- [ ] 所有数值带量纲

> 豁免：`is_template: true` 的模板文件不受 `name = 文件名` 约束，其余校验全部适用。
