# 卡片族谱（暂定三分）

> 依据：`Doc/Cards/卡片工程总结.md` 的三条客观变量——语言特性、模型能力、镜头表达。
> 目的：把卡片（token 生成物）按「变化频率」拆开，让可复用的部分独立存活，顺带顺应模型能力这个客观事实。
> 「暂定」：三分是当前工作假设，随实测调整；本文件只定职责，不定目录、不定验收。

## 一、为什么切

卡片的效果取决于三条客观变量：语言特性（写多紧）、模型能力（接不接得住）、镜头表达（换镜即重建）。三者变化频率不同——描述改得慢、镜头改得中、模型/通道换得快。若全写进一张卡，任何一层改动都会逼整卡重跑、旧证据全废。

切分只为一件事：**让变化频率低的部分独立存活**，高频率的部分单独替换。

| 卡型 | 回答的问题 | 对应变量 | 管什么 | 变化频率 |
| --- | --- | --- | --- | --- |
| 描述卡 | 长啥样 | 语言特性 | 主体、场景、风格、外貌、材质 | 慢 |
| 镜头卡 | 拍什么 | 镜头表达 | 景别、机位、运镜、焦点、切换、时间轴 | 中 |
| 成品卡 | 谁出的 | 模型能力 | 拼装正文（同样是单表）＋元信息出处锚：各拼装卡 hash、节点模型 id | 快 |

## 二、三张卡

### 2.1 描述卡（长啥样）

- 回答「它长什么样」：主体、场景、风格、材质、外貌。
- 写法：具体度旋钮（见工程总结 1.x）——可观测属性优先，气质词当押注。
- 复用：跨镜头卡、跨模型。换机位、换模型都不需要重写描述卡。
- 现例：`RAG/portraits/`、`styles/`、`stylings/`；Circle12/14 的 4 行地貌卡。

### 2.2 镜头卡（拍什么）

- 回答「怎么拍」：景别、机位、运镜、焦点、切换、时间轴。
- 写法：段结构可执行，帧号／秒数只是标签（工程总结 2.2）；不承担跨镜一致性（工程总结 3.x）。
- 复用：跨描述卡——同一套镜头计划可以拍不同主体。Circle14 就是固定地貌、只换镜头卡。
- 现例：Circle12/14 的 `card-camera.md` 实验；RAG 已有绑定基础卡的派生 `cameras/`，顶层独立 `cameras/` 暂不建。

### 2.3 成品卡（谁出的）

- 回答「这一版是谁出的」：表体＝所有拼装卡正文的逐字节拼接（只剥 frontmatter、只拼接，不抽字段、不改写），元信息锚定出处。
- 写法：与上面两卡相同的单表格式（frontmatter ＋ 一张两列表）；差别只在 frontmatter 的出处键，至少两项——① 所有拼装卡片的 hash（卡名＋SHA256 前 12 位，口径同 `RAG/README.md`）；② 节点模型 id（通道 webappId ＋ 生成节点的模型标识）。任务号、日期、实扣、判读结论可选。
- 复用：最低。拼装卡任一 hash 变、或模型／节点换代，旧成品卡即失效。
- 现例：`video/prompt-video.txt`（表体原文）＋ `*.run.log` ＋ `ledger.json` 是成品卡的存档件；入库后由 `RAG/.../evidence.md` ＋ `prompt.txt` 承担同一条锚定逻辑。

## 三、族谱关系

```text
描述卡 ──┐
         ├── 逐字节拼接 ──> 成品卡（通道／模型／参数／日期） ──> 产出与验收
镜头卡 ──┘
```

- 1 张描述卡 × N 张镜头卡 = N 种拍法。
- 1 张镜头卡 × M 张描述卡 = M 个主体。
- 同一份原文、同通道重跑 = 同一成品卡的新 run 记录；同卡的两次运行也会抖（Circle14 同 prompt 切点差 6–8 帧）。
- 成品卡自身 hash 由「拼装卡 hash ＋ 节点模型 id ＋ Task id + 表体」共同决定；任一变化就是新成品卡。
- 换通道／换模型 = 新成品卡，旧卡标失效。
- 组合时从最便宜的一层换起：先换镜头卡，再换描述卡，最后才动成品卡（动它＝换模型，最贵）。
