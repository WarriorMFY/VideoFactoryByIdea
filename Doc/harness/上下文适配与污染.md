# 上下文适配与污染：长期记忆的保质期

> 缘起：2026-11-23 22:27 用户口述。「大模型的上下文压缩功能使其具备了一定的长期记忆，但是长期记忆在某些时候不一定是好事，关键在于『上文记忆』是否与当下任务相适配，如果不适配将是『上下文污染』，不如直接新建一轮对话。」

## 一、先分清两件事

| | 事实记忆 | 结论记忆 |
| --- | --- | --- |
| 是什么 | 发生过什么、跑了什么、花了多少 | 当时认为什么是对的 |
| 有没有保质期 | 基本没有（账、任务号、图） | **有**，换目标就过期 |
| 该放哪 | 文件（log、proj、账） | 文件 + 版本号，且标注「在什么条件下成立」 |

压缩摘要的问题不在"记得多"，在于**它把两类记忆压成了同一种东西**：一堆没有时间戳、没有前提条件的结论，混着事实一起塞进下一轮的起点。

## 二、本会话里真实发生的四次污染

**① 拿上文的答案答下文的问题。** 摘要里存着 Circle28 的剧本《雨夜·灯笼铺》和"七阶段"，我起手就用它抽了四张风格锚——而当下指令是"新建循环、先确定剧本"。用户原话：「剧本都没定，自己跑啥呀」。这不是遗忘，是**把上一轮的正确答案套到这一轮**。

**② 同一编号两套含义，没人裁决。** `core.md §9.1` 写 L3 = 「两镜同人同场景」，我在对话里说 L3 = 「一场戏两个人」。压缩把两个版本都保下来了，因为它们不冲突——它们只是不同时期的话。用户原话：「我真的不懂你说的 L1，L2，L3，到底啥意思啊」。**记忆越多，定义漂移越难被发现**。

**③ 按旧状态推进。** 摘要里写着多个圈"已暂停""已结轮"，于是我把"暂停"当成当下的语境，延续旧项目的节奏，而不是按新指令重建起点。

**④ 过度谨慎，把判断也交出去了。** 摘要里存着用户两次纠正（擅自裁帧、擅自改出片宽度），我随后连"该不该继续跑"都推给用户问。**记住教训是对的，把教训泛化成"什么都不许动"就变成了新的错误。**

## 三、判据：什么时候该开新一轮

四条里中任何一条，就该新建对话：

1. **目标换了**——不是同一项目、也不是同一方向的连续迭代。
2. **上文结论已被推翻或已过期，但仍在被引用**（②③ 就是这种）。
3. **需要先解释术语才能继续**——术语一漂移，说明定义只活在对话里。
4. **本轮已出现"按旧结论行事"的返工**（①）。

反过来，该留着的情况只有一种：**同一项目的连续迭代，且踩过的坑没写进文件。**

## 四、真正的解法：把可写的写走，别让记忆干文件的活

- **能被写进文件的，一律写进文件。** 文件有版本、有 diff、可裁决；对话记忆是一锅没有时间戳的结论。
- **术语第一次定义就落盘**，并且只在一处定义（本仓库的做法是 `reference/core.md` 作唯一数值源）。
- **开新一轮时只带三样**：文件指针、当前目标、不能碰的红线。不带上文的结论。
- **结论要带前提**：「在 X 条件下成立」比「X 成立」有用得多，前者过期时能被识别出来。

## 五、一句话

**记忆的价值不在长度，在与当前任务的适配度。** 一段不适配的长期记忆，比没有记忆更贵——它会让你很确定地做错事。
