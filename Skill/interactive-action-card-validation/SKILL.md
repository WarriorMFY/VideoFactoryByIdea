# 交互动作卡验收

> 原名 `action-card-validation`（已废除）→ `action-card-validation-v2`（2026-11-15 更名为本名）。目录同步为 `Skill/interactive-action-card-validation/`。

**验收对象：交互动作卡。** 不是所有动作卡都归这里管。

## 0 触发条件

两条**同时**成立才触发；任一不成立则本技能不适用，记 `N/A`。

| # | 条件 | 通过 | 不通过 → `N/A` |
| --- | --- | --- | --- |
| 0.1 | 动作主体 ≥ 2 | 卡内有两个及以上可动施动者（人 / 兽 / 械斗单位），各自有动作且归属可查 | 单人练习、单人套路、独角戏训练卡 |
| 0.2 | 主体间产生动作交互 | 至少一条**跨主体**的作用关系：攻防、格挡、抓持、推撞、击中、被击飞 | 各打各的并行动作、无接触也无反馈的流程卡 |

`N/A` 不是 `FAIL`：卡不入本技能，也不算验收通过，不得进入 L2–L4。判 `N/A` 时须写明缺哪一条，并指出该卡该走哪套口径。

```json
{"layer": "0", "verdict": "N/A", "answers": [{"id": "0.1", "verdict": "PASS|N/A", "reason": "引卡内原文"}]}
```

# L1 静态结构检查

> 设计规范（不属于验收项），两份配套读：`reference/field-semantics.md`——五字段各自填什么、协作分工；`reference/ai-action-card-design-observations.md`——空间让渡给模型、因果与接触由卡掌握。两份文末均有「本仓库实测修订」，与正文冲突时以修订节为准。

输入一张**已通过触发条件**的交互动作卡，输出 `PASS` / `FAIL` 与失败项。只查格式，不判动作可行性；FAIL 即阻断入库。

| 检查分类 | 检查项 | 检查规则 | 成功模式 | 失败模式 |
| --- | --- | --- | --- | --- |
| 格式 | 1 主体结构 | 一张卡＝frontmatter＋1 个一级标题＋0–2 条引用声明＋1 张关键帧主表，主表前允许 1 个二级标题（纯格式，无外引） | `# 标题` 下 1 张两列表，表上 1–2 行 `>` 声明 | 出现第二张表；一级标题 ≠ 1；出现三级及以下标题；表格外有独立正文段落 |
| 格式 | 2 两列 | 主表每行严格 2 列（纯格式，无外引） | `｜ K0 / 阶段 / 0% ｜ 五元组 ｜` | 出现第 3 列（如备注列、时长列） |
| 格式 | 3 左列帧号 | 左列 `K{n} / 阶段 / 进度%`，n 从 0 连续、不跳号，进度单调递增至 100（纯格式，无外引） | K0 0% → K1 33% → K2 66% → K3 100% | 跳号（K0 直接到 K2）；进度倒退；缺 `%` |
| 格式 | 4 右列五元组 | 五段按 `角色 → 武器/接触 → 目标 → 位移 → 同步` 排列，每段 `键=值`、`；` 分隔（详规：`reference/field-semantics.md` 总纲表） | `角色=…；武器/接触=…；目标=…；位移=…；同步=…` | 缺键、乱序、多键；`；` 切出无键名段 |
| 格式 | 5 元信息 | frontmatter **恰好 2 键**：`name`、`description`，缺一不可、不许多写（纯格式，无外引） | 两行 frontmatter | 缺 `name` 或 `description`；出现第 3 个键（`type` / `scope` / `level` / `source` 一律删） |

附注：L1-4 的接触键两种写法均可——`武器接触` / `武器/接触`。

判定：5 项全过即 `PASS`；任一不过即 `FAIL`，阻断入库，不得进入后续验收层。

# L2 语义与时序检查

**查什么：当前语义是否清晰、是否自相矛盾、时间轴是否自洽。**

前置：**触发条件（0.1 / 0.2）成立**，且 **L1 必须 PASS**。触发不过记 `N/A`，L1 FAIL 的卡不进 L2。

分三类：**清晰度**、**矛盾**、**时序**。八项全部答完才算通过；任一项 `FAIL` 即整层 FAIL。

| 检查分类 | 检查项 | 检查规则 | 成功模式 | 失败模式 |
| --- | --- | --- | --- | --- |
| 清晰度 | 1.1 主体检查 | 每个动作、部位、受力方都要写清归属（详规：`reference/field-semantics.md` §1、§3） | 「主体A的防御手」「主体B的胸口正中」 | 只写「手」「胸口」「对方」而无归属；同一动作可归两方而卡内未定 |
| 清晰度 | 1.2 功能检查 | 同类部位（两只手、两只脚）禁用空间语义（前 / 后 / 左右），须改用功能语义（详规：`reference/field-semantics.md` §1 替代词；实测依据：`reference/ai-action-card-design-observations.md` 修订表第 2 行） | 防御手、进攻手、主攻手、另一只手、承重腿、发力腿 | 前手、后手、左手、右手、前脚、后腿 |
| 矛盾 | 2.1 同帧矛盾 | 同帧五元组串成一句话读不得互斥——① 时序词（`已` / `后` / `未停顿`）与「同一拍」一致；② 同一事实跨键复述时须是同一回事、不得互斥（同键不得自相反）；③ `同步` 须写两主体在同一拍各自在做什么（详规：`reference/field-semantics.md` §5「同拍爆发 / 物理对齐」） | 「主体B的拳到达的同一拍，主体A的防御手恰好立在接触位置」 | 武器/接触写「手腕内侧」而同步写「拳背下沿」；「原地站立」与「产生后坐力」并存；`同步` 通篇写接触细节、无时间关系 |
| 矛盾 | 2.2 跨帧矛盾 | 物件、姿态、接触关系纵向连续，无无交代的跳变（详规：`reference/field-semantics.md` §2「明确接触状态」） | K0 格挡成立 → K1 转为拨带 → K2 推中 → K3 无接触并脱离 | 上一帧称无接触、下一帧称仍贴着；受力肢体跨帧换边 |
| 时序 | 3.1 进度锚点 | 0% 为稳定起点、100% 为稳定终点，两端都不是瞬时事件（详规：`reference/field-semantics.md` §2「强调发力瞬间」——该写法仅适用末帧，不得用于 0%） | 0%「格挡成立并顶住」；100%「收势定格与背部触地同步」 | 0% 写成「撞上的瞬间」「明显撞击点」；100% 写成「正在倒下」 |
| 时序 | 3.2 跨帧接口 | 两帧之间新增的事件须有归属主体与起止；相邻两帧不得姿态重叠——后一帧要求的部位若前一帧已在该位置，须写出起点与位移差，否则模型无动作可演、只会冻结（详规：`reference/field-semantics.md` §4） | 「防御手自胸前向前迎出」——有主体、有起点有终点 | 某主体整段区间无动作归属，从静止跳到完成；上一帧已把下一帧的姿势摆好（K0「抬至身前」→ K1「竖立在中线」），该主体在视频里全程不动 |
| 时序 | 3.3 事件密度 | 单帧可判读事件 ≤ **2 件**（一个攻防动作＋一个反馈），事件数与区间时长不要求等分（详规：`reference/ai-action-card-design-observations.md` 修订表「帧数不是越多越好」） | K1「拨开＋主体B上身歪斜」＝2 件 | 一帧四件：拨开 → 直击 → 双脚离地 → 蹬地前贯 |
| 时序 | 3.4 受力与终态 | 位移方向须与受力方向一致；100% 终态须可辨（失衡 / 后退 / 倒地 / 离场）（详规：`reference/field-semantics.md` §3、§4） | 「胸口受力 → 向后倒飞 → 背部砸地扬尘」 | 位移与受力反向或无受力来源；终态既未失衡，也未后退 / 倒地 / 离场 |

附注三条：

- **1.1 例外**：承前省略且归属唯一，视为通过。
- **姿态重叠**：两帧各自成立、但相邻帧之间某部位没有位移差，静态读不出问题，动态会停住——模型只按「状态差」插值，没有起点就没有动作。实测（2026-11-15）：同一张卡四轮视频里主体A 的防御手 0→1.5s 位置不变；把「抬起迎出」从 K0 移入 K1 后，两轮均出现可见的迎出位移。
- **时序不查**：不查事件数是否按进度等分（因果要连贯，不要均匀）；不查位移能否累加、终态坐标能否反推（属空间精度，与「放弃微观坐标」相悖；连左右手都锁不住的通道，反推终态无意义）。

## 输出

```json
{"layer": "L2", "verdict": "PASS|FAIL", "answers": [{"id": "1.1", "verdict": "PASS|FAIL|PARTIAL", "reason": "引卡内原文"}]}
```

- `id` 取 `1.1` / `1.2` / `2.1` / `2.2` / `3.1` / `3.2` / `3.3` / `3.4`。
- 每条结论必须引卡内原文，不写「感觉不对」。
- 说不清、判不了即记 `FAIL`，理由写清缺哪项。
- 八项全部答完，不得跳项。

## 判定

八项全 `PASS` 即 `PASS`；任一 `FAIL` 即整层 `FAIL`，阻断入库，不得进入 L3。`PARTIAL` 不阻断，但须写明理由并在报告中标出。

## 记 `PARTIAL` 的情形

只允许这三类，其余一律 `PASS` 或 `FAIL`：

1. 100% 为瞬时事件，且用户已裁定接受该收势写法
2. 区间时长偏松或偏紧，但不构成事件断裂
3. 受力方向正确、终态可辨但幅度偏小（仅轻微后仰、半步踉跄）

`FAIL` 只指向卡内可改的文字，不指向模型能力；模型画不出不改卡。
