# 首帧图生视频通道

一条通道吃透即可，换通道先查节点真名再改本文件。

## 通道

| 项 | 值 |
| --- | --- |
| appId | `2113790012012720129` |
| 首帧位 | `140:image`——**只有这一个图位，没有尾帧入口** |
| 提示词 | `142:value`（字段名是 `value`，不是 `prompt`） |
| 时长 | `133:value`，浮点，step 0.1，可写任意秒 |
| 画幅 | `115:aspect_ratio` = `16:9 (Widescreen)` |
| 清晰度 | `115:megapixels`，常用 `0.6` 与 `0.92` |

`0.6` 实出 1056×608，`0.92` 实出 1312×736（对齐 720p 素材用后者）。

## 实测价（2026-11）

| 档位 | 单条约 |
| --- | --- |
| 0.6MP / 5s | 22 积分 |
| 0.92MP / 5s | 37–47 积分 |

同一条任务不同次的价格会浮动（实测 36.55 / 42.33 / 46.41 都出现过），估价按上限算。

## 已知限制

- **出入必然重绘**：0 帧近乎逐像素复制（NCC 0.99），一动就重绘一次，之后才稳定。所以「传入首帧」不等于「锁死首帧」。
- **没有尾帧入口**：想做首尾双帧强锚，这条通道做不到，只能改用「上段尾帧当下一段首帧」链下去，代价是误差累积。
- **小配件不保**：首帧锚保住结构与画风，不保眼镜、饰品这类小物，段中会消失。
- **结构改写只在局部**：能把指定位置的一处构件弄断、弄掉、弄碎，但尺度和形态会缩水，详见 `limits.md`。

## 换通道

1. `python scripts/rh_api.py --info <appId>` 查节点真名。
2. 改本文件与 `scripts/run_one.py` 的 `APP`、节点表。
3. 节点名以接口返回为准，不许照抄记忆。
