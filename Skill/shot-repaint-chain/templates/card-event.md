# 事件卡模板

用于段内要出现一处**可命名变化**的镜头。与延续卡的区别是：必须有时刻、位置、结果态三件套，不能只描氛围。

```markdown
---
name: <段>-<场景>-<事件名>
desc: <一句话：场景 + 机位 + 是什么事件>
axis: 事件（<触发>）→ 过程（<松动／坠落／碎裂>）→ 结果（<缺口／残骸／余尘>）
---

| 项 | 内容 |
| --- | --- |
| 主体 | <主体与场景，同延续卡> |
| 起始态 | <事件发生前的构件状态；这是唯一需要写全的部分> |
| 动作时序 | 0–<x>s 静止，只有<介质>在动；<x>–<y>s <事件触发>；<y>–<z>s <过程>；<z>–<段长>s <收束> |
| 接触事件 | <断口与谁相撞、碎片彼此> |
| 位移 | <哪部分动、落点在哪；不写米／厘米> |
| 结果态 | <末态：缺口、残骸、尘；写形态不写数量> |
| 禁止 | 不切镜、不改机位、不让人物入画、<主体本体不移动> |
```

```text
同一<场景>、同一<主体>、同一机位与同一冷暖布光，写实电影质感，镜头不动。

事件：<画面哪一区域>的<哪个构件>先<松动表现>，随后<脱离／倒塌／坠落>，<落在何处>，<碎裂成若干>，<附带尘或屑>；随后<余尘下沉>，<留下什么>。<主体本体>纹丝不动。

不要切镜，不要改变景别，不要出现人物，<不要出现文字／保留原有文字>。
```

## 三条硬要求

1. **位置**：事件坐标必须写在主体所在区域。写在画面边角时，模型只会在那儿补氛围，不做叙事。
2. **时刻**：给事件一个发生点（第 1.0–1.4 秒），不要写成「逐渐」。
3. **结果态**：必须能一句话说清「事后画面比事前少了什么／多了什么」。

## 预期管理

事件会被简化：整段结构变成一处构件，砸落变成散落。写卡时就按**简化后仍成立**的形态写，见 `../reference/limits.md` 第 2 条。
