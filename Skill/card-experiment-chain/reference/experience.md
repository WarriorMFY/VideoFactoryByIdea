# 经验沉淀

`experience/` 存**经人工验收**的通道／模型事实，一条一文件。第一版为空目录（`.gitkeep`），表示尚无条目通过验收。

## 录入门槛

| 阶段 | 条件 | 谁 |
| --- | --- | --- |
| 提候选 | 同一现象在两条独立链或两次独立任务中复现 | AI：只在当轮 `log.md` 列候选，不建文件 |
| 进目录 | 候选成立 **且** 用户明确说「这条算数」 | 用户点头 → AI 才落文件，标 `provisional` |
| 升稳 | 第三条样本 + 用户再次确认 | 用户 |
| 标废 | 出现反例：改 `refuted`，保留文件并指向新条目 | AI 标，用户确认 |

## 硬约束

1. **不许自升**：未经人工验收不得写文件；AI 不得自行改 `status`。
2. **一条一文件**，文件名英文短横线，如 `timing-fixed-frames.md`。
3. **只增不改**：结论变了就新开条目，旧条目标 `refuted`，不删。
4. **只写事实**：现象 + 证据 + 判读 + 影响；不写推测，不写建议清单。

## 条目格式

```markdown
---
title: <一句话结论>
scope: <通道/appId 或模型>／<画幅/时长>
status: provisional | confirmed | refuted
since: <YYYY-MM-DD>
evidence: <链号、task id、帧号、可复算的数字>
---

## 现象
## 证据
## 判读
## 对流程的影响（改 SKILL 哪一道闸门 / 哪个 reference）
## 边界与反例
```

## 与循环的关系

- 循环进行中：结论只进 `log.md`。
- 循环结束：AI 先列「沉淀候选」，用户逐条点「过」才写 `experience/`。
