# t2v 判据（无锚版）

> i2v 有首帧锚可量 NCC；t2v 无锚，判据只剩三样：时长、运动、事件完成度。
> 数字先出，眼睛后看——顺序反了会被「看起来挺好」骗（Circle15 前科）。

## 一、时长

| 项 | 判据 |
| --- | --- |
| 偏差 | 实测 vs 请求 ≤ 0.25s 算合格（5s 档实测 5.17s 属正常，编码帧率导致） |
| 档位 | `205:select` 1-11（5-15s），**5s 是硬下限**；要 3-4s 用 i2v 首帧通道（`133:value` 浮点） |
| 段边界 | 剪辑需求与模型档位对撞时，段长听模型的——3-5s 一切是剪辑习惯，不是模型能力 |

## 二、运动（分区运动 max，灰度差 0-255 尺度）

| 值 | 档位 | 含义 | 适配场景 |
| --- | --- | --- | --- |
| < 2 | 静 | 只有云动/粒子，主体没动 | 定场空镜 |
| 2-8 | 微 | 呼吸级微动 | 人物站立对话、静物特写 |
| 8-25 | 中 | 主体动作可读 | 常规叙事镜头 |
| > 25 | 大 | 快动作/大运镜，易糊 | 打斗、追车——先验证再依赖 |

分区位置有意义：运动峰值落在边缘格（1/3/7/9）= 运镜/入画出画；落在中心格（5）= 主体原地动作。

## 三、事件完成度（人工，必须写记录）

- 提示词的事件链是否**按序发生**（因果链，不是关键词堆）
- 终态是否命中（最后一帧该有的东西在不在）
- 结论必须写成「哪个事件没发生 / 哪个动作走形」，不许写「整体不错」

## 四、什么算边界点

| 现象 | 归类 | 处置 |
| --- | --- | --- |
| 事件发生但动作走形 | **能力边界** | 记下来，别重跑 |
| 事件根本没发生 | 提示词没锁住 | 改卡（事件链写法），重跑 |
| 时长严重超差（> 0.5s） | 通道异常 | 记 charged，报警 |
| 同 prompt 两次差异巨大 | 采样噪声 | 属正常，多跑取稳，不算失败 |

## 五、成本纪律

- 同参数同档位也会跳档（10.54 vs 20.57、11.22 vs 24.33），**估价按上限**；
- 一条一账，`charged` 记原文，不推算；
- 预算告急时优先降分辨率（720P→480P），不降时长档位（改档会破坏组内可比性）。
