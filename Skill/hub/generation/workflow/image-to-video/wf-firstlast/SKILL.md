# wf-firstlast · 首帧 + 尾帧 → 视频（自带图直跑）

**只跑一步**：两张锚图 + 一段提示词 → 一条 mp4，外加一组对齐数字。
它的价值在**约束力**：两端都是像素锚，量出来的 NCC/SSIM 就是这条通道能给的上限。

> **位置**：`Skill/hub/generation/workflow/image-to-video/`。调通道、产媒体，同输入重跑不唯一（采样），按判据归 `generation/`。
> **不是第二个网络出口**：凭证与端点常量复用 `runninghub/scripts/rh_credential.py`，脚本自动向上找仓库根，技能移动不失效。

详情见 `reference/workflow-api.md`。

## 两条命令

```powershell
P = Skill/hub/generation/workflow/image-to-video/wf-firstlast

# 1) 跑一条（首帧 + 尾帧 + 提示词；默认 720 宽 / 49 帧 ≈ 3 秒）
python $P/scripts/run.py --first 起点锚.png --last 掠过锚.png `
  --prompt "镜头固定，三人并排骑扫帚从远处灯塔边飞近" `
  --width 720 --frames 49 --out out.mp4

# 2) 量一条（首/末帧 vs 两张锚，出 NCC + SSIM + 交叉项）
python $P/scripts/measure.py --video out.mp4 --first 起点锚.png --last 掠过锚.png
```

## 判读（沿用 `pixel-anchor` 的尺度）

| NCC | 含义 |
| --- | --- |
| ≥ 0.93 | 锁住，锚的像素被端帧继承 |
| 0.80 – 0.93 | 大体对齐，但已被重画 |
| < 0.80 | 只是语义相似 |

**交叉项必须低**（首帧 vs 尾锚、末帧 vs 首锚都该在 0.35 上下）。交叉项高 = 首尾串了，八成是图位填反。

## 铁律

1. **205 是首、204 是尾。** 模板标题写反了，只信连线；填反的表现是「成片倒着走」而不是报错。
2. **一跑一账。** 跑前跑后都读 `remainPoint`，只认差值；不同次同参数实扣会不一样。
3. **先量后看。** 先出数字再看片，否则会被「看起来像」骗过去。
4. **中段不归锚管。** 两端锁死 ≠ 中段不乱；背景漂移/主体走样属正常边界，要治得靠更多关键帧，不是靠加大提示词。
5. **改尺寸只动 197/202。** `122` 的宽高由 `201` 反推，直接改会被覆盖。
