# 命中判读与导出细则

> 只定义「agent 如何据关键词判命中」与「windows 怎么给」；抽帧参数在 `preparing.md`，不在本文件重复。

## 判读（看 sheet-*.png）

1. 先通看全部拼图页，再下结论；不能只看第一页。
2. 命中判据：画面中**确实出现**关键词所指的对象／文字／事件。只看画面，不靠猜；相似但不确定标「存疑」，不算命中。
   - **形似物必须放大排除**：拼图缩略后，折扇／伞／轮状机械／举杯动作都可能被误认成盾。命中前打开原尺寸单帧看结构——盾有连续盾面＋盾钮／握把；折扇有扇骨与中心轴，边缘呈放射齿；饮品杯是透明容器。判错一次就要回看该物所有帧，统一排除。
   - **模糊帧过滤**：运动模糊／过曝／烟尘遮挡导致物体轮廓不可辨的帧，标「模糊」并排除，不因为它可能含目标就计入命中。拉普拉斯方差可辅助（真人电影数值天然低于卡通片头，不能只靠阈值），最终以目视轮廓可辨为准。
3. 拼图间隔默认 0.3–0.5 秒，只作导航：命中处记下角标时间与帧号，再用 `--start/--end` 缩小范围、`--step 0.1` 重抽一次细看，确认精确起止。
4. 关键词是抽象动作（如「撞击瞬间」）而非静态物时，拼图不可靠——放弃判读，明确告知须通看全片。

## windows 格式

`extract.py --windows` 接受 JSON 字符串或 JSON 文件路径，形如：

```json
[
  {"start": 1.2, "end": 2.0, "label": "盾牌"},
  {"start": 3.4, "end": 3.4, "label": "击中"}
]
```

- `start`/`end`：秒；`end == start` 表示只导关键帧、不切片段。
- `label`：产物文件名前缀，缺省 `hit`。
- 时间值先按第 3 步细看校准，不直接照抄 0.5 秒拼图的角标。

## 导出规则

- 关键帧：取窗口**中点**那一帧，导出 `<out>/keyframes/<序号>-<label>-<time>.png`；`end==start` 时即该帧。
- 分段视频：导出 `<out>/clips/<序号>-<label>-<start>-<end>.mp4`，用 **FFmpeg 无损流拷贝**（`-c copy`），不重编码、无画质损失。
- 流拷贝只能从关键帧起切，实际起点可能早于请求值（本次实测请求 3.0s 实际约 2.8s）。脚本回读片段真实时长，在 `extract.json` 写 `clip_mode=ffmpeg-stream-copy`、`clip_actual_duration`、`clip_estimated_start`；判读时用回读值，别用请求值。关键帧仍由 cv2 按帧精确取，不受此影响。
- `extract.json` 逐窗记录产物路径（统一 `/` 分隔）与实际时间；未命中就给空数组 `[]`，不编造窗口。
- Windows 下 cv2 的 `imread` 读不了中文路径：核验关键帧用 PIL 打开；脚本写盘已用 `imencode`+二进制写规避乱码文件名。

## 边界

- 不修改源视频，不跨 `--out` 目录写文件。
- 不做评分、不判断片段好坏；片段能否用由后续人工／实验链验收。
