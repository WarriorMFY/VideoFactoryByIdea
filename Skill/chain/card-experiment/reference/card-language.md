# 卡片的语言特性、模型能力与镜头表达

> 与 `card-format.md` 并列的写法建议，不作强制校验，不判 `PASS`／`FAIL`。
> 纲要三条：**语言特性**（写法本身决定约束力度）、**模型能力**（模型对这类指令的接收力度）、**镜头表达**（换镜即重建，画面只能换来一版脑补）。前两条决定「一句话能不能立住」，第三条决定「换镜后还是不是同一个东西」。
> 论证与缘起见 `Doc/harness/`：左右问题见「动作卡不限左右限逻辑」，一致性问题见「肖像一致性-视觉优先与分层约束」。
> 来源：`Doc/Cards/卡片工程总结.md`（2026-11-19 迁入）。

## 一、语言特性

### 1.1 具体度＝约束力度旋钮

卡片里的每个描述，都是给下游大模型的一道约束。描述越抽象，约束越松，模型的先验脑补越多；描述越具体，约束越紧，成片越可控，但也越容易僵。

所以「写多细」不是文风问题，是**旋钮**：它决定这一行交给模型多少自由。

### 1.2 光谱：同一只狐狸

| 写法 | 约束力度 | 模型仍需脑补的 | 典型结果 |
| --- | --- | --- | --- |
| 灵狐 | 最松 | 物种、颜色、体态、气质全靠先验 | 神秘感容易出，但形态与颜色不可复现 |
| 白狐 | 较松 | 色相、体量、姿态 | 大体收敛，细节各跑不同 |
| 白色狐狸 | 较紧 | 姿态、环境 | 颜色基本可复现 |
| 通体雪白、尾尖带霜的赤瞳白狐 | 最紧 | 几乎只剩姿态 | 可复现性最高，但容易僵硬失真 |

规律：每加一个**可观测**的属性（颜色、数量、形状、材质、位置、动作），约束紧一档；加的是气质类词（灵、神秘、优雅），约束几乎不变，甚至更松。

### 1.3 怎么用

| 场景 | 建议写法 | 理由 |
| --- | --- | --- |
| 要复现、要过验收 | 落到可观测属性，颜色、数量、位置优先 | 这类词最容易被模型当硬条件执行 |
| 要氛围、要惊喜 | 只给抽象定位，主动留白 | 把脑补空间还给模型的先验 |
| 同一行抽象与具体混写 | 抽象在前定性，具体在后收束 | 顺序反过来，具体词易吞掉抽象词 |
| 内容与镜头卡冲突时 | 优先删具体细节，保留抽象定位 | 内容与细节一多会反压景别与构图（Circle12／14 实测：内容会撑宽景别、压掉远景） |

边界：「具体＝好」不成立——具体只换取可复现性，代价是先验里的好细节被压掉；抽象只换取想象空间，代价是方差。不改变信息量时是旋钮，一旦增删信息行，就是换卡，按当轮入库循环执行。

## 二、模型能力

### 2.1 接收力度是模型端的事

语言特性决定「约束有多紧」，但还要看听话的一方能不能听懂：同一句话，模型可能根本没有对应的表征。写得多紧是一回事，接不接得住是另一回事——**写得再紧，模型接不住就是没写**。

### 2.2 实测接收力度

本项目累计实测，不同指令的接收力度差一个量级：

| 指令类型 | 接收力度 | 实测表现 |
| --- | --- | --- |
| 左右（左手、向右拨） | 几乎没有 | 模型只有「动作」，没有「解剖」：Circle2 出现第三条手臂，Circle4 写着左手、模型换手但动作逻辑不误（详见 `Doc/harness/动作卡不限左右限逻辑.md`） |
| 秒数（s） | 有一点，不多 | 能带动段数、总时长这类粗结构；具体时点对不上（Circle12：9s 三镜卡首刀 5.58s，秒数被当标签） |
| 帧数（第 N 帧切、124 帧） | 约八成 | 段结构与段内镜头状态对得上 72.5–92.5%，平均约八成（Circle14）；但单帧级切点仍不可执行——0／6 命中，偏差 0.5–1.2s |

更细的事实条目见 `evidence/`（`mirror-agnostic`、`count-not-counted`、`framing-ratio-not-exact`）。

### 2.3 怎么用

| 场景 | 建议写法 | 理由 |
| --- | --- | --- |
| 模型接不住的指令 | 换成可接收的表达：功能位、画面位置、段结构 | 接不住的词不生效，还会挤占语义预算 |
| 多部件同动 | 只留一个主动部件，其余写「随动」 | 额外变量超限会让部件增殖（左右是典型） |
| 抽象词收尾 | 当「风格押注」用，不当「稳定约束」 | 脑补方向由模型先验决定，随模型换代漂移 |

- 接收力度是模型当前的能力边界，不是卡的属性。写卡按当前通道实测写，别把押注固化进卡。
- 验收时把两类失败分开记：写了但模型听不懂，与根本没写紧；前者换表达，后者补信息。

## 三、镜头表达

### 3.1 镜头一动＝重新画一版

卡片里的镜头句，不是对「已有画面」下机位指令，而是对「下一版画面」下文字描述。模型没有持续的三维场景记忆，每切一次镜头，它按文字把世界重建一次——「同一事物」不是原物体转了角度，而是重画了一个像它的东西。变量固定也不变结局：固定的是描述，不是被描述的那个东西。

两份实测：

- Circle10：像素锚只活在第 0 帧（对源图 NCC 0.956），镜头一动掉到 0.402；换景别＝换渲染域，跨域互比只有 0.47–0.61。
- Circle14：同一张地貌卡＋同一张镜头卡，段 2 是潭心泉眼、段 3 是盘根特写、段 4 又回到山谷，但每段的山形、水系排布都是重新长出来的；r2 段 4 甚至把「远景」长成中景溪流。

### 3.2 推论

| 事实 | 含义 |
| --- | --- |
| 镜头卡定的是「怎么拍」 | 景别、机位、运镜、切换能对齐；「拍到的是不是同一个东西」不保证 |
| 跨镜一致性＝重建相似度 | 不是同一实体的旋转，而是两次独立生成之间像不像 |
| 语言管状态，不管长相 | 「静止」「不许动」能执行；「树形多粗」「水怎么流」执行不了（同 `Doc/harness/肖像一致性-视觉优先与分层约束.md`） |
| 换镜＝换渲染域 | 不同景别的画面不能跨域互比一致性 |

### 3.3 怎么用

| 场景 | 建议写法 | 理由 |
| --- | --- | --- |
| 一卡多段 | 每段信息自足，不写「同上」「依旧」 | 切镜后没有「上」，每段都是新世界 |
| 跨镜要认出是同一处 | 每段保留一个可识别地标（泉眼／盘根／瀑布），措辞复用 | 地标是跨段重建的锚，比整体描述稳 |
| 主体必须严格一致 | 用图承担：首帧／尾帧接力、参考图，语言只写语义定位 | 视觉层是硬约束，语言层是软约束（同 `Doc/harness/肖像一致性-视觉优先与分层约束.md`） |
| 验收跨镜一致性 | 按景别分层比，不跨域打一个分 | 换 L4 即换渲染域，跨域比较无效 |

一句话：镜头卡写的是「描述」，不是「机位」。模型每镜都按描述重拍一版，一致性只能靠锚——文字锚管认得出，图锚管长得像。
