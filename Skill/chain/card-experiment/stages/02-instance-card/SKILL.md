# 阶段② 填实例卡

## 何时用

- 轴与元卡已定（①交付物齐），要产出可直接投递的卡；改版必须新开链，旧卡不删。

## 何时不用

- 只想改措辞、不打算送模型。
- ④ 阶段改的是通道参数，不是卡内容。

## 三个动作

1. **选骨架并填实体**：复制元卡，按 `templates/instance-card.md` 的裁剪提示收缩——只留 frontmatter、一级标题、轴说明、单张两列表；每个 `<占位>` 换成具体实体（地名、物种、季节、秒数），**占位符不许留到实例卡**。
2. **配伴生卡**：`templates/companion-fixed.md`（固定变量）＋`companion-anti.md`（反向），合计字数 ≤ 主卡 10%。
3. **自检**：逐条过下表，任一条 FAIL 就回改，不许「先送看运气」。

## 送模型前的自检表

| 检查项 | 判据 | 常见失分 |
| --- | --- | --- |
| `name` 对齐 | frontmatter `name` = 文件名（独立卡）或目录名（`<name>/card.md`） | 改名忘改 frontmatter |
| `description` | 必填，≤200 字符，写清这张卡管什么 | 抄元卡描述 |
| 表结构 | 至少一张表，每数据行**恰好 2 列**；一张主表只承载一维，两维就两张卡 | 三列拼信息表；动作＋镜头挤一张 |
| 占位符 | 全文无 `<...>` 形式的占位 | 漏填一个就整段失效 |
| 左右词 | 同类部位禁解剖学与空间语义（左／右／前／后），用功能位替代（持械手／防御手）；画面位置（如「左侧三分之一」）不受此限。完整表述见 `../../reference/card-format.md` §三 | 「左手挡、右手推」「前手」 |
| 形容词 | 不写无法验收的形态词（美感、氛围、气势） | 「画面更高级」 |
| 伴生卡占比 | `(fixed+anti)/main ≤ 10%`，脚本实数打印 | 压主卡凑比例（禁止） |

交付物：`card-instance.md`、`card-fixed.md`、`card-anti.md` 三份快照，加各自 sha1 与字数，交给 ③ 拼装。

通过线：自检表七项全 PASS，且伴生卡占比实数 ≤10，才能进 ③。
