# ⑥ 出视频

一段一条任务。判出来的不是两态而是三态，**半过是 AI 时代唯一新增的权力**。

## 步骤

1. **写段卡**：首帧图 + 因果事件链（发生了什么 → 先后 → 终态）+ 时长。
2. **核余额**：剩余积分 < 剩余段数 × 单条估价先问用户（价见 `core.md` §3）。
3. **出片**：首帧进图位，段卡全文进文本位，不抽字段不改写。落 `run.json`（任务号/实扣/尺寸/帧数）。
4. **量**（脚本在先）：首帧 NCC、时长偏差、帧间差曲线、hf 中段比、黑边。
5. **判**：过 → 入账定稿；半过 → 修复；不过 → 记边界点，改卡再抽。
6. **记账**：修复也算一次，一笔不漏。

## 观察纪律（判之前先定怎么看）

圈 30 的教训：判据没量错，是**看的样本不够**——四等分抽帧（0 / 1/3 / 2/3 / 末帧，间隔 1.67s）跳过了压纸的中段，于是把「纸被压平」判成「纸没变」，整段被误判为能力边界。

1. **状态改变类戏眼**（纸边、水面、缝线、表情、火苗）必须原速或慢放逐帧看。
2. **抽帧条只判**：构图、接缝、溶解、多手、尺寸、黑边。要抽就按事件点抽或间隔 ≤0.5s。
3. **否定结论必须在动态上复核一次再落笔**；只有动态复核后仍失败，才允许写进 `core.md` §4 当能力边界。写错一条边界比多花 20 积分贵得多——下一圈会主动绕开一个不存在的坑。

## 判据

| 判什么 | 用什么 | 阈值 |
| --- | --- | --- |
| 没跑偏 | 首帧对关键帧 NCC | ≥0.90 |
| 时长对 | `|实际−请求|` | ≤0.25s |
| 是运镜还是溶解 | hf 中段/两端 | <0.75 且中段不快 → 溶解 |
| 落点稳 | 末三帧 nccB 斜率 | 一帧涨 0.08 以上＝被硬拽 |
| 方向对不对 | 只能看 | 与关键帧朝向是否一致 |

## 半过修复（按代价从低到高）

`retime` → `只重跑末段` → `局部重绘` → `首尾帧锁` → `换首帧重抽`。
方向类问题直接跳到最后一招：**朝向是被首帧钉死的，prompt 改不动**（两版 ncc 均 0.7622）。

## 通过线

- 戏眼成立且保持到末帧（不是中途出现又消失；按上面的观察纪律看，不靠抽帧条）。
- 首帧 NCC ≥0.90、时长偏差 ≤0.25s。
- `charged` 已入账；废片保留，不许删。

## 产物

`Log/Circle<N>/video/runs/<镜>/`：`out.mp4`、`prompt.txt`、`run.json`、`metrics.json`、`strip.png`（抽帧条）。

## 不过怎么办

- 805 / 超时 → 零扣费原样重试，别改 prompt。
- 溶解（两画面叠影）→ 两锚跨度太大，拆两镜或加雾作遮罩，别加抽。
- 自动推镜 → 无法关闭，近景改从中景起，预留推近余量。
- 长镜头想超 5–6s → 拆段，或 8s 档用 129 帧一次出（末帧反而更稳）。
