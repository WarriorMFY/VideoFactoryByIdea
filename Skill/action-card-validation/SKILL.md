# 动作卡分层验收入库

## 目标

接收一张待入库的动作卡，四级递进验收。任一层 FAIL 即阻断入库。

**核心原则：卡是标准，模型是执行者。模型画不出不改卡，记通道限制。**

## 输入与输出

- 输入：Markdown 动作卡（frontmatter + 一级标题 + 轴说明 + 两列主表）
- 输出：`{ "status": "PASS/FAIL/PARTIAL", "level": "L1~L4", "reasons": ["帧/字段/原因"] }`

---

## L1 静态结构（零成本 / 脚本）

1. **四段结构**：正文只允许 frontmatter、一级标题、轴说明、单张主表。`##` 标题数为 0，一级标题 1 个，表格分隔行 1 条。
2. **两列**：左列 `K{n} / 阶段 / 进度%`，右列严格五元组定序 `角色 → 武器接触 → 目标 → 位移 → 同步`。
3. **主体前缀**：部位与武器必须带归属，写「主体A的盾」不写「盾面」。
4. **连贯词**：卡若声明一气呵成，查真实停顿词（停住、稍待、随即停下）。脚落地、重心落定这类姿态词不算停顿，不报错。

## L2 语义与物理（极低成本 / LLM 自检）

分两组，共 14 问，全部答完才算通过。

### 组一 · 七类矛盾（查「格与格打架」）

| 类 | 查什么 | 实例 |
| --- | --- | --- |
| A 同帧矛盾 | 五行串成一句话读，是否互斥 | 武器接触=刺入 vs 同步=对齐，同帧两说 |
| B 跨帧矛盾 | 物件状态纵向对比是否连续 | K0 盾心对准 vs K1 盾缘撞击；剑在肘后直接到咽喉，无出剑 |
| C 物理不可能 | 器械插入体内后，受动方还能否自由移动 | 剑插喉咙仍后退；剑刃一百厘米却写「没入至护手」 |
| D 因果错误 | 每个位移的动因是否为本帧动作 | 剑刺却写「撞退」，剑不推人 |
| E 几何不自洽 | 距离 / 臂长 / 兵器长能否算通 | 盾面最远 70，却写胸距 110 时已撞上 |
| F 缺信息 | 遮住其余帧，单帧能否独立成立 | 未写盾径与剑长，几何无法验算；未写谁持盾谁持剑 |
| G 精度失真 | 数值换算是否等价 | 170 cm 写成「一步半」 |

### 组二 · 武术指导七问（查「格子全对但打不出来」）

| 问 | 症状 | 实例 |
| --- | --- | --- |
| 力从哪来 | 屈肘却要刺穿、重心不动却要贯穿 | 肘弯 90° 加前脚落定，却要求剑尖没入 |
| 站得稳吗 | 前冲无重心转移 | K1 缺「重心前移至左脚」 |
| 握得住吗 | 未交代左右手分配 | 同 F |
| 够得着吗 | 算下来差十几厘米 | 155 cm 触及范围 vs 需 155 cm 的两端验算 |
| 打中会怎么动 | 钝击写僵直、穿刺写后甩 | 剑已入喉，反应仍是盾击造成的后仰 |
| 之后被什么限住 | 器械在体内还能自由移动 | 同 C |
| 兵器用得对吗 | 盾心对着人、下帧盾缘撞；刃背尖朝向错 | 盾击靠盾面推退，盾缘是砍 |

**两组互补**：组一查逻辑自洽，组二查物理可行。组一发现「刺入与对齐互斥」，发现不了「屈肘刺不穿」；组二反之。

### 通过标准

14 问答完，每问在日志留一行结论。**任何一问答不上来，不算通过。**

## L3 关键帧视觉（中成本 / 文生图）

取峰值帧（通常 K2）送验。

1. **Prompt 逐字照抄该帧原文**，不改写、不换算、不补词、不调语序、不掺其他卡内容。
2. 唯一允许追加防干扰句：`画面干净，主体占画面主导，动作清晰可读，无特效、无遮挡，中性画风。`
3. **落盘校验**：改完 Prompt 必须跑 `scripts/verify_prompt.py` 比对，确认与卡片该帧逐字一致。口头声称已改而实际未落盘，会白烧一轮。
4. **判据看「同步」列，不看「武器接触」里的动作词**。同步列给出的落点就是本帧终态。
5. **不可判的项不判 FAIL**。静帧无法区分「刚入 2 cm」与「抵住」，记 PARTIAL 并写明原因。
6. 保留键名格式可能出「图注版」——别当废图，它是诊断基线：图注=模型的理解，画面=模型的执行，两者不一致即说明是画不出而非读不懂。图注行为不稳定，同一 Prompt 未必复现。

## L4 视频（高成本 / 人工）

1. 显式覆盖通道默认值（时长、分辨率），否则费用翻几倍。
2. **判定必须通看全片，由人下结论。**
3. 抽帧只做段落导航，间隔 ≤0.1 秒，不得据此单独判 FAIL。0.57 秒一帧的抽样，盾撞与刺入这类 0.1–0.2 秒事件必然落空。
4. 关注：节奏是否拖沓、打击是否有受力停顿、多段发力是否连贯。

## L2 审查专属 Prompt

```text
你是极其严格的武术指导兼物理引擎。审查以下动作卡，找出它打不出来的地方。

【组一 逻辑自洽】
1. 同帧矛盾：把每帧的五行串成一句话读，读不通的地方在哪？
2. 跨帧矛盾：同一件物品在相邻帧的状态是否连续？姿态是否跳跃？
3. 物理不可能：器械插入体内后，受动方还能自由移动吗？
4. 因果：每个位移的动因，是不是本帧动作造成的？
5. 几何：把每个距离数字写成算式，臂长 + 兵器长 vs 目标距离，算得通吗？
6. 缺信息：遮住其余帧，这一帧能否独立成立？
7. 精度：口语换算与原始数值是否等价？

【组二 武术指导】
8. 力从哪来？发力链（脚→腰→肩→臂→兵器）哪一环断了？
9. 站得稳吗？重心与支撑面是否支持这个动作？
10. 握得住吗？谁持什么、腕角是否使得上力？
11. 够得着吗？伸展 + 兵器能否触达目标点？
12. 打中会怎么动？生理反应是否匹配击打性质（钝击 vs 穿刺）？
13. 之后被什么限住？有没有器械卡在体内却要求自由移动？
14. 兵器用得对吗？刃/背/尖/护手朝向，盾面还是盾缘？

【动作卡内容】
（插入卡片）

【输出】
仅返回 JSON：
{"status":"PASS|FAIL","reasons":["K2 位移=... 与 武器接触=... 互斥","K1 屈肘 90° 无法刺穿，应展臂至 15°"]}
```

## 脚本

| 脚本 | 用途 | 用法 |
| --- | --- | --- |
| `verify_prompt.py` | L3 前置校验，Prompt 与卡片逐字比对 | `python verify_prompt.py <card.md> <prompt.txt>` |
| `run_l3.py` | L3 送验，读 `# L3` 段出图，快照落 `<out>.prompt.txt` | `python run_l3.py <prompt.txt> <out.png>` |
| `run_l4.py` | L4 送验，读 `# L4` 段出视频，默认套三个节点覆盖 | `python run_l4.py <prompt.txt> <out.mp4>` |
| `draw_sheet.py` | 视频抽帧拼图，仅作导航 | `python draw_sheet.py <video.mp4> --cols 4 --rows 4` |

四个脚本共用同一份 prompt.txt：`# L3` 段首行为该帧原文、`--no` 行为负向词；`# L4` 段首行为 K0–K4 拼接。改一处，四者同步。

换通道先用 `runninghub_app.py --info <appId>` 查节点 id，再传 `--app` / `--prompt-node` / `--node`。`run_l4.py --bare` 跳过默认覆盖。

## 三条铁律

1. **L2 必须重跑**。卡改过一列，之前的 L2 结论作废，不许说「改动很小」。
2. **改卡的边界**：卡自身逻辑错误（矛盾、算不通、缺因果）→ 改；模型画不出 → 不改，记通道限制。为通过验证降低动作标准，等于伪造证据。
3. **判据回字面**。验收前逐字重读该帧，不凭印象、不按自己对动作的预期。

## 归档

- 卡副本入 `Log/CircleN/`，hash 与 `Doc/` 源卡一致
- 日志必含：阶段表、送验表（轮次/taskId/消耗/结果）、成本总账（含无效消耗）、返工流水、结论与判据修正
- 证据保留：送验 Prompt 快照、出图、视频、抽帧图，文件名带轮次后缀不覆盖
